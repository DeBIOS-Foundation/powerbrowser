# Phase 15 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note.** GUI-08: the Panorama surface in the organising main-area slot. Groups are named
boxes at user pixels on one canvas. A group tiles its cards in one uniform grid, and when the
cards no longer fit it stacks them behind an Expand pill. Tabs in no group are loose cards on the
canvas itself. Card drags use pointer events. A box resizes from eight grips, and push-away keeps
groups and loose cards from overlapping after every gesture. A canvas/tree toggle shows two views
over one SQL-persisted group model. Cards carry PNG last-view snapshots. The canvas reads and
writes only via the single chrome-side writer path; sessionstore stays restore-authoritative
(never sessionstore-coupled — Bugzilla 1221050). Never fork or patch Theia core; never modify
Gecko outside the patch stack.

**Binding constraints.** The 13-01 spike verdict RED still binds: the tab strip **STAYS TOP** —
no contract below moves or re-skins the strip. While a group is active, the Browsing strip shows
that group's tabs, the loose tabs and the current tab;
Coding's tab bars and Organising are not filtered, and no tab is closed, moved or detached by the filter.
The organising slot hosts the canvas/tree surface; the Phase 14 placeholder copy is listed
under Retired copy and does not ship. Sketch 002 organising view is the visual reference; the
Panorama research note and `15-PANORAMA-GAP.md` (the Firefox 44 Panorama reference) are the
interaction authority.

**Inherits from 14-UI-SPEC** (do not contradict): design system `none`, spacing ramp, typography
delegation (3 sizes / 2 weights), color tokens, 60/30/10 split, focus idiom, motion baseline,
copy rules (product named "PowerBrowser", plain language, real on-screen next step, no internal
identifiers), mode names **"Coding"** / **"Browsing"** / **"Organising"**, tabs invariant asserted
by the status-bar chip. This spec states only what this surface adds or extends; unmentioned
13/14 contracts stand unchanged.

## Canvas Geometry

The geometry contract. A row whose Key is one or more identifiers joined by ` × ` is a const
row: its Value numbers, read before the first `(`, equal that const in the tree. A row whose Key
is a backticked selector and a property is a CSS row: that property is declared once in the rule
for exactly that selector in `modes.css`, as that many px. `verify-gui08-canvas-geometry` reads
both through `scripts/lib/ui-spec.mjs`, and every top-level numeric const in
`organising-widget.ts`, `organising-tiling.ts` and `organising-geometry.ts` has a const row. Rows
with a Key of two or more plain words are description and are not compared. Box positions are
user pixels, never snapped. Hairline borders are `1px var(--color-border)` and `radius-sm` (4px)
is on cards, boxes and tree rows.

## Typography

Three sizes, two weights. The only `font-size` literals under `.pb-org-*` are 12, 13 and 14, and
`verify-gui08-canvas-geometry` enforces that. Font families are delegated to the Theia theme.

| Role | Size | Weight | Line height | Applies to |
|------|------|--------|-------------|------------|
| Body | 14px | 400 (600 when active group) | 1.5 | Box titles, tree group titles, expanded-stack heading, empty-state heading and body, error-bar text, rename input |
| Label | 13px | 400 (600 on active toggle segment) | 1.4 | Base card title, tree rows, toggle segments, zoom steps, close glyph, blank-preview label (line height 1.3, frozen) |
| Caption | 12px | 400 | 1.5 | URI captions, tiled and loose card titles, stack count, pile count, Expand pill, zoom readout, tree count, empty-group hint |

heading `.pb-org-expand-heading` is 400. There are no headings above 14px.

## Color

Locked sketch theme `sources/themes/default.css`, 60/30/10 split by painted area. No hex value
outside it, apart from the frozen translucencies listed below.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1c1b22` `--color-bg` | Organising host, canvas host, tree background, card preview background |
| Secondary (30%) | `#2b2a33` `--color-surface`, `#35343f` `--color-surface-raised`, `#3f3e4a` `--color-border` | Toolbar, error bars, group boxes, tree sections, expanded panel; cards on surface-raised; hairlines |
| Text | `#fbfbfe` `--color-text`, `#9a99a8` `--color-text-muted` | Primary ink; secondary ink, inactive segments, active-group border |
| Accent (10%) | `#00a6f5` `--color-primary` | Reserved list below |
| Accent, light | `#8ad4ff` `--color-accent` | The Expand pill text only |
| Destructive | `#ff848b` `--color-danger` | Close Group confirm button only (`.pb-org-close-confirm .theia-button.main`) |

**Accent reserved for (exhaustive):**

1. `:focus-visible` rings on every Panorama control: `outline: 2px solid var(--color-primary); outline-offset: 2px`.
2. Active Canvas/Tree toggle segment ink, with 600.
3. The Expand pill text, in `--color-accent`.

Items 1-4 of the 14-UI-SPEC list (address pill, mode toggle, suggestion row, current-setup row)
stand unchanged and belong to their own surfaces. Accent is never a general fill and thumbnails
carry no accent treatment. The active group is marked by a `--color-text-muted` border plus title
600, on canvas and tree, not by accent. A valid drop target shows a translucent slot that opens in
the target group's grid, not an accent outline.

**Frozen translucencies:** stack count, pile count and Expand pill background `rgba(0,0,0,0.72)`;
expanded-stack scrim `rgba(0,0,0,0.55)`; rubber band `rgba(255,255,255,0.08)`; drop slot
`rgba(255,255,255,0.10)`; blank-preview hatching `rgba(255,255,255,0.02)`; drag ghost shadow
`0 8px 22px rgba(0,0,0,0.55)`. Opacities: source card while dragging 0.7, ghost 0.9, band-enclosed
loose card 0.45, resize grip 0.6.

### Contrast

Pairings from 13/14-UI-SPEC: `#fbfbfe` on `#1c1b22` ≈ 16:1; `#fbfbfe` on `#2b2a33` ≈ 13:1;
`#9a99a8` on `#2b2a33` ≈ 5:1 (AA for secondary text and captions). `#8ad4ff` on the 0.72-black
pill over `#2b2a33` is above 10:1. The active group is never shown by colour alone: title 600
carries it too. `#ff848b` on `#2b2a33` ≈ 5:1 — the Close Group control pairs destructive ink with
its explicit label and a confirmation step, so colour is never the sole carrier.

### Focus

Every Panorama control shows `outline: 2px solid var(--color-primary); outline-offset: 2px` on
`:focus-visible` (WCAG 2.4.7 / 2.4.11, same idiom as 13/14-UI-SPEC): toggle segments, New Group,
zoom steps, error-bar Retry, box and tree close buttons, cards, tree rows, box and tree titles,
the rename input, the visible resize grip, and the empty-state action. Cards are reached by
roving tabindex within their scope (see Interaction Contract, Cards).

### Motion

Baseline `transition: all 0.15s ease` (sketch-locked, carried); zoom transform 0.15s; the drop
slot moves at 0.12s; the drag ghost and the dragged card have no transition. Opening a tab from a
card uses the stock tab-open path with no authored animation. `prefers-reduced-motion` removes
transitions on the canvas layer, cards, the resize grip and every toolbar control. Group data
paints with skeleton boxes until first load, never a spinner.

with a next step that is a real control on screen, and carries no internal identifier (no pref
key, sentinel, port, table name, `group_id`, bounds (other than the resize grip's spoken size of the user's own box, which Chris accepted at 22-01 C1 item 5), URI-scheme internals or raw exception text).

## Interaction Contract

### Toolbar, views, bars

- Toolbar row: [Canvas | Tree] segmented toggle, "New Group", and the zoom cluster (−, readout,
  +, 100%) on the right. The zoom cluster is hidden in Tree view (hidden, not disabled, so the
  toolbar never shows a dead control). Load and save error bars sit under the toolbar.
- Canvas and tree render from one `GroupModel` fed by the single chrome-side writer path.
  Flipping the view never reloads, never loses the active group, and never needs confirmation.
- Zoom steps through `ZOOM_STEPS` (25%-200%) with a 100% reset; the readout shows the level.
  Zoom scales the canvas layer transform only: group bounds and card data are untouched, and
  thumbnails scale by CSS with no re-capture.
- Tree view: each group is a section (title, tab count, ×) over 32px rows of title and mono URI
  caption, with the same rename, close and empty-group rules as the canvas. The tree lists groups
  only; loose cards have no tree representation. Order and membership always match the canvas.

### Groups on the canvas

- A group is a box: header (title, × close) over a card area, with eight resize grips. Moving is
  a drag on the header. Resizing works from any edge or corner: `n` and `w` move the origin, and
  the size is floored at 200×144. The `se` grip is visible, focusable (`role="slider"`, labelled
  "Resize group"), and arrow keys resize it in 8px steps, or 32px with Shift.
- Groups never overlap. After a move, resize, draw or loose-card drop, `pushAway()` moves every
  other group and loose card clear by 12px. The box the user placed never moves.
- **Cards grid, they never scroll.** All cards in a group share one size, the largest at which
  every card fits (`fitTiles`, gap 8, aspect 0.72). A tiled card is a fill-height preview over a
  12px title; the URI line is hidden and the card tooltip carries title plus address.
- **Too small to grid → stack.** Below 84×60 per card the group fans up to 5 cards, offset 4px,
  with a count badge and the "Expand" pill. Only the front card takes the pointer.
- **Expanded stack.** "Expand" opens a panel over the canvas, outside the zoom transform: the
  group title as heading, "Done", and every card at base size (220px) in a wrapping, vertically
  scrolling list. Done, Esc or a scrim click closes it.
- Clicking a header or the box background makes that group active (muted border plus title 600).
  Opening a tab marks its group active. Which tabs the Browsing strip shows follows the active group (see Binding constraints).
  Double-click or Enter on a title renames it: Enter commits, Esc cancels, an empty commit
  reverts, 60 character cap, duplicates allowed.

### Loose cards

- A tab in no group is a **loose card** on the canvas itself: 160×115, no panel, no border
  around the set, no label. A loose card that has a stored position is drawn there. One with no
  position is laid out on a line `LOOSE_MARGIN` above the canvas bottom, left to right. With zero
  groups the line never starts above the "No tab groups" panel's bottom edge plus `LOOSE_MARGIN`;
  in a host too short for both, the canvas grows and the host scrolls. When that
  line is full, the rest pile at its end: up to 4 cards drawn, offset 4px, with a count of the
  unplaced remainder. Piled cards behind the front one take no pointer.
- Loose cards take part in push-away like groups do.
- Loose cards render whenever ungrouped tabs exist, **including when there are zero groups**. In
  that state the "No tab groups" panel and the loose cards are both shown.

### Gestures

- **Draw a group.** Press on empty canvas and drag a rubber band. On release, a band of at least
  30px on one axis becomes a new "Untitled group" at that rectangle (floored at 200×144) with
  its title in edit mode. Loose cards whose centre is inside the band join it; they go to 0.45
  opacity while enclosed. Esc cancels. A smaller band counts as a click and does nothing.
- **Card drag** uses pointer events, since native drag and drop does not run inside the remote
  `<xul:browser>`. It starts after 4px of travel. A copy of the card (0.9 opacity, shadow)
  follows the pointer while the source card stays in place at 0.7.
  - Over a group: that group's grid re-packs and a translucent slot opens where the card will
    land. Dropping there joins the group at that index.
  - On empty canvas: the card becomes loose at the drop point. It does not create a group.
  - On a loose card: the drop path checks for a group before a card, so the card lands on the
    field as a loose card.
  - Released anywhere else: nothing changes.
  - A group emptied by a drag is dissolved (last card out). Its tabs survive.
- **Open a tab:** double-click or Enter on a card. A single click does not open the tab. Opening
  switches to Browsing for a page, or Coding for an editor or the Welcome view. It then
  activates the open widget, or reopens the tab through the opener if it is closed (NG-008).
  Opening never closes, moves or detaches any other tab.
- **Close Group:** × opens the destructive confirmation. Confirming closes exactly that group's
  tabs and the box, then the status-bar flash appears. Cancel changes nothing. If the closed
  group was active, activity passes to a remaining group or to none, never to a removed box.

### Cards

Preview first, then title, then URI. A card with a thumbnail shows it as an `<img>` with an
error guard. A card without one, or whose image failed, shows a hatched panel carrying the tab's
own title (`pb-org-card-blank-label`, 3-line clamp). It never shows a broken-image glyph or a
spinner. The URI line is present only when the tab has a real address; internal keys never
appear. Cards are focusable. Enter opens the tab, and arrow keys move focus within the card's
scope.

**Roving-focus scopes:** each group's card area, the set of visible loose cards on the canvas (in
model order, hidden pile cards skipped), and the expanded-stack card list. Each scope has exactly
one tab stop.

| Gap | Disposition |
