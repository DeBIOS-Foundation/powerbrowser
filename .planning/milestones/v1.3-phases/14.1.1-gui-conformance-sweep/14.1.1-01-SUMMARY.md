**A dropped overlay now paints the lost-view line with no click and recovers in one Reload; web tab ids carry a per-session nonce the WidgetFactory checks, so a persisted layout can no longer re-create last session's tabs; and the live check stopped manufacturing the focus evidence it asserted on.**

## Accomplishments

- **G-14.1.1-4 closed.** `WebTabWidget.publish()` now dispatches the geometry message through `channel.request` and folds only the unknown-tab outcome into lost view. Geometry is the one message chrome answers on every layout change and the only one sent while the user is idle, so its reply is the only evidence available that the overlay is gone before the user touches anything. `reload()` re-issues the open in the *same* click when `settle()` has only just discovered the loss, so recovery costs one Reload rather than two.
- **G-14.1.1-5 closed.** A module-level `WEB_TAB_SESSION` discriminator makes every minted id `wt-<session>-<n>`, and the `WEB_TAB_FACTORY_ID` factory throws on any id not minted this session. The stock `ShellLayoutRestorer.convertToWidget` catch turns that throw into a dropped widget — the supported opt-out, with zero Theia-core edits (`diff-theia-core: PASS -- zero changes inside @theia/*`). The class comment's wrong claim that the frontend origin changes every launch was replaced by the measured truth.
- **G-14.1.1-20 closed.** No `FocusEvent` is dispatched anywhere in the run. The pill assertion stands on the strip-selection binding alone, and `derive()` now goes red if that binding disappears, so a green pill can never mean nothing.
- **The instrument got three new plants and a derived expectation.** `--self-test` boots ten sessions: the clean control green, nine plants red, each naming its own drift.

## Decisions Made

- **Only the unknown-tab outcome marks the view lost in `publish()`.** Reusing `lostReply()` would let a `timeout` reply blank a live page during a slow frame — a worse defect than the one being closed. Stated in the method's own comment so a later reader cannot "simplify" it back.
- **Both Reload arms share one `reopen()` helper.** The plan said to keep the existing lost-view branch unchanged; extracting the identical four lines rather than duplicating them is behaviourally identical and a smaller diff. Recorded here because it is a visible departure from the literal instruction.
- **`WEB_TAB_SESSION` is not a security token.** Documented at the constant. Authorisation for a group-channel request stays the chrome-side origin wall; the nonce only discriminates a described id from a minted one. It reaches no URI — `git grep WEB_TAB_SESSION -- docs/ theia/extensions/tab-uris/src` shows it only in `web-tab.ts`, with `TabUriRegistry`/`uriOf` untouched.
- **The plant reaches the WidgetManager's factory table, not the DI binding.** By the time a plant runs, the `WidgetFactory` binding is already resolved into `WidgetManager.factories`; that cached map is the seam `getOrCreateWidget` actually calls, so it is the seam the plant must patch to restore the pre-fix behaviour honestly.
