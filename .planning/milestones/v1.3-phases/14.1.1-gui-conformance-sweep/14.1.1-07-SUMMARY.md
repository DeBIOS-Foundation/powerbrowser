# Phase 14.1.1 Plan 07: Attributable Plant Scoring Summary

## Accomplishments

- **Every scored failure message now leads with one of fifteen stable tokens.** `newtab:` `popup:` `context:` `align:` `nav:` `pill:` `push:` `dropdown:` `lost-view:` `walk:` `restore:` `store:` `thumbnail:` `close:` `shell:`. The set, what belongs in each family, and *why* anchoring matters are documented in a block comment above `assertReport`. Three message classes are named as deliberately outside it: the derivation failures (they lead with the file path they name and run before any plant), a plant that could not be applied, and a phase that threw — each reports a broken instrument, each is caught by its own check in `selfTest`, and no plant may be scored on any of them.

- **The discriminating observable shipped and it works.** `report.afterA.titleLabel` reads `P.widget.title.label`. `WebTabWidget.refreshTitle()` puts the served page's `<title>` there only once `applyState` — the state push — has delivered it, falling back to the URL and then to "New Tab". The self-test proves both halves in one run: `state pushes ignored` goes red naming `push:` with `the tab's strip label reads "HTTP://127.0.0.1:35983/a" ... expected "Web tab A"`, while `the pill is keyed on focus` goes red naming `pill:` **and green on `push:`** — the widget there still hears chrome; only the bar's binding is broken. Two plants that could not be told apart at all before this plan are now scored by two different true assertions.

- **Scoring is anchored, and the eleven expects are pairwise-unique.** `failures.some(f => f.startsWith(testCase.expect))`, with the evidence filter moved to `startsWith` too, so the two lines printed under each `ok` are the plant's own family. Every plant went red naming its own prefix on the first full self-test run — no expect needed a second choice.

- **The guard that makes the defect unrepeatable, with a standing record that it can say so.** `expectTableFaults(cases)` is a pure function refusing (a) any expect that does not end in `:` and (b) any expect shared by two plants. Before it ever looks at the real table — and before any browser session boots — it is run against three literal fixture tables and prints one `ok` line per fixture: a duplicate rejected naming `"a:"` and `(x, y)`, a bare `pill` rejected naming `"pill"`, and a well-formed table accepted. The third fixture is the one that matters most: without it, a guard that returned a fault for everything would look like a working guard.

- **WR-13 closed by deletion.** `restoreBefore.includes(...)` is gone. `getOrCreateWidget` does not add to the shell, so its condition could not be false under any product behaviour. `restore.mainIdsAfter` stays on the report and in `printReport` — demoted from assertion to record, the same demotion 14.1.1-01 applied to `shell.currentWidget` — with the reason and the WR-13 reference written where the assertion used to be.

- **Both verifications green at the final tree.** Clean run PASS (7 alignment reads, max delta 0.48 CSS px); `--self-test` PASS with the clean control green and all 11 planted faults red. `git -C upstream diff` empty. `powerbrowser/` untouched — no build or packaging step ran, so the concurrent session's uncommitted `jar.mn` never entered the artefact under measurement.

## Decisions Made

- **The strip label is waited on inside the existing `until` predicate, not in a second wait.** Waiting for a condition with a timeout and then asserting it is the pattern the pill already uses in this file: a wait bounds a green run, it cannot manufacture one. Folding it into the same predicate means a plant that starves it pays the same 8s it already paid, so nothing moved closer to the 20s BiDi `script.evaluate` budget that bit plan 06.
- **Three message classes stay outside the closed set.** The plan explicitly exempted the derivation failures on the grounds that they run before any plant and no plant scores them; a plant that could not be applied and a phase that threw are the same argument — instrument reports, not contract reports, each already caught by its own named check. Written down in the file rather than left implicit.
- **`no-geometry` is scored on `align:` and the empty-alignments guard also emits `align:`.** Under `no-geometry` the rect pair IS measured (and misaligned), so the plant's red is the real comparison; the guard covers the different failure of measuring no pair at all. Both are the alignment contract, so one family is correct for both.
