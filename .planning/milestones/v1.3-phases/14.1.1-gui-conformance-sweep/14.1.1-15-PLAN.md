<objective>
Resolve the contradiction between a shipped refusal string and the doc comment two lines above
it: the copy ends with a next step the same comment says the user cannot take.

Purpose: `setups-service.ts:147` ships *"Power Browser can't open this tab in its own window.
Select a terminal or editor tab first, then try again."* while `:141-145` states that the
command carries no palette label, so re-invoking it is not an affordance the user has, and the
only real next step on screen is selecting a different tab. The verification confirmed the dead
surface: `SETUPS_OPEN_DEPENDENT` is declared with an id and no label
(`setups-commands.ts:35-37`) and a grep across `theia/extensions/**/src` finds only the four
lines that declare and register it — no invoker, no `MenuContribution`, no
`KeybindingContribution`. CLAUDE.md requires the next step in a user-facing error to be a real
affordance on screen.

**The decision this plan takes, and the one it rejects.** Drop the trailing clause so the copy
states only the affordance that exists. The alternative — giving the command a palette label so
the clause becomes true — adds a new user-facing surface to a conformance sweep, needs its own
spec row for the label, and would be a Phase-14 feature decision rather than a conformance fix.
The clause is dropped; if the command is later made reachable, the clause can be restored in the
same two files.

Output: a two-file, one-commit copy change that keeps `gui09-setups-copy`'s set equality green.
</objective>
