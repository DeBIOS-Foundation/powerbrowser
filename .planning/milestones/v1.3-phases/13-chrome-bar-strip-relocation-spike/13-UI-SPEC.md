# Phase 13 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note.** This phase builds GUI-06: a top chrome bar (back/forward/reload,
address input with suggestions, new tab, mode toggle) as a toolbar-like
`@powerbrowser/*` contribution, plus the strip-relocation SPIKE verdict (green →
Variant B strip work in Phase 14; red → Variant-A fallback, strip stays top).
Tab feel + navigation only: no bookmarks strip, no per-tab close/mute, no
browser menu. Never fork/patch Theia core; never modify Gecko outside the
2 hook-only patches; Theia is the default GUI with stock chrome reachable.
New-tab opens via the stock-window escape until GUI-02.

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — shadcn deliberately not initialized (see rationale) |
| Preset | not applicable |
| Component library | Theia side: `@theia/core` widgets only (toolbar contribution, tree/table-free custom dropdown). No new widget framework. |
| Icon library | none added. Theia supplies codicons for its own chrome; the bar uses codicons (`chevron-left/right`, `refresh`, `plus`, `lock`) — no new icon set. |
| Font | Delegated: `--theia-ui-font-family` (UI) and `--theia-code-font-family` (URI captions), fallbacks `system-ui, sans-serif` / `ui-monospace, monospace`. No font-family literal in `@powerbrowser/*`. |

same standing rationale as 01-UI-SPEC — nothing in this repo is a Vite/Next
app, and Theia-side widgets inherit the `--theia-*` theme so a second token
system would fork theming and break the rebrand-without-recompile promise.
The chrome bar's Power-Browser-specific values come from the locked sketch
theme (`sources/themes/default.css` in the sketch-findings skill), expressed
as a CSS layer inside the `@powerbrowser/*` contribution, overridable by the
`customize.css` user layer.

**Sources:** sketch-findings-Power-Browser SKILL.md + `references/chrome-bar-and-navigation.md`
(Variant A locked, naming locked, MVP scope locked), `sources/themes/default.css`

Declared values (all multiples of 4). Sketch `--space-*` ramp adopted verbatim;
`12px` is a declared step, not an exception.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, suggestion-row text gap |
| sm | 8px | Bar-internal gaps (button ↔ pill ↔ toggle) |
| md-gap | 12px | Address-pill horizontal padding, dropdown row padding |
| md | 16px | Dropdown vertical padding, default element spacing |
| lg | 24px | Not used in Phase 13 (reserved) |
| xl | 32px | Nav button hit area (32×32), address-pill height, suggestion-row min-height |
| 2xl | 48px | Not used in Phase 13 (reserved) |
| 3xl | 64px | Not used in Phase 13 (reserved) |

Fixed geometry (prescriptive): chrome bar height **40px**, full-bleed, single
row. Address pill `border-radius: var(--radius-full)` (9999px). Dropdown rows

Exceptions:

| Exception | Value | Why it stands |
|-----------|-------|---------------|
| Theia toolbar/tab-strip geometry around the bar | Theia stock | The bar is a contribution beside stock regions; it does not resize them. Strip-overflow and many-tab handling stay Theia stock behaviour. |
| `radius-full: 9999px` | non-scale | Pill shape token from the locked sketch theme; applies only to the address pill. |

## Typography

Theia side is delegated — the table below binds the delegation to exact
rendered sizes (3 sizes, 2 weights). No `font-size` / `font-weight` literal
may appear in `@powerbrowser/*` that is not one of these three sizes.

| Role | Size | Weight | Line Height | Applies to |
|------|------|--------|-------------|------------|
| Body | 14px | 400 | 1.5 | Address input text, suggestion titles |
| Label | 13px | 400 (inactive) / 600 (active) | 1.4 | Mode-toggle segments, nav-button tooltips (Theia stock), tab-count chip |
| Caption | 12px | 400 | 1.5 | Suggestion URI captions (`--theia-code-font-family` mono), dropdown footer hint |

600 (semibold) is reserved for exactly one use: the **active mode-toggle
segment**. Nothing else in this phase sets 600. There are no headings or
display type in this phase — the bar carries no `h1`–`h6`.

## Color

Locked sketch theme (`sources/themes/default.css`), genuine 60/30/10 split by
painted bar area.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1c1b22` (`--color-bg`) | Window / workarea background behind the bar |
| Secondary (30%) | `#2b2a33` (`--color-surface`) bars, `#35343f` (`--color-surface-raised`) hover, `#3f3e4a` (`--color-border`) hairlines | Chrome bar fill, address-pill fill, suggestion dropdown fill, hover raises |
| Text | `#fbfbfe` (`--color-text`) primary ink, `#9a99a8` (`--color-text-muted`) secondary ink | Labels, captions, placeholder, inactive segments |
| Accent (10%) | `#00a6f5` (`--color-primary`), hover `#0090d4` | See reserved-for list below — nothing else |
| Success | `#8ad38a` | Lock glyph in the address pill on secure contexts only |
| Destructive | **none declared** | No destructive action exists in this phase |

**Accent reserved for — exhaustive list:**

1. Address-pill focus border/ring.
2. Active mode-toggle segment (fill or ink — planner picks one, never both).
3. Keyboard-highlighted suggestion row (active-descendant background wash).

Nothing else. Accent must never be used as a general fill, and no second
brand hue may be introduced (neutrals + one restrained blue, per sketch).

### Contrast

`#fbfbfe` on `#1c1b22` ≈ 16:1 — AAA at all three type sizes. `#fbfbfe` on
`#2b2a33` ≈ 13:1 — AAA. `#9a99a8` on `#2b2a33` ≈ 5:1 — AA for secondary text
and captions; muted ink must never be the sole carrier of the active-toggle
or active-suggestion state (weight + accent carry it too). Do not introduce a
mid-grey text colour that would break these pairings.

### Focus

Every bar control (nav buttons, address input, toggle segments, suggestion
rows via roving active-descendant) shows a visible focus indicator:
`outline: 2px solid var(--color-primary); outline-offset: 2px`
(WCAG 2.4.7 / 2.4.11, same idiom as 01-UI-SPEC's shell outline).

### Motion

Baseline `transition: all 0.15s ease` on every interactive bar element
(sketch-locked). Suggestion filtering is synchronous-feeling: no spinner for
local history/bookmark matches; a row-level progress shimmer appears only if
a provider exceeds 150ms.

## Copywriting Contract

Product rules inherited from 01-UI-SPEC and CLAUDE.md: every user-facing
string names the product as **"Power Browser"** where a product name is
needed, states the problem in plain language, ends with a next step that is
a real affordance on screen, and carries **no internal identifier** (no pref
key, sentinel, port, URI-scheme internals, or raw exception text). Naming is
fixed: **"chrome bar"** everywhere, never "browser toolbar".

| Element | Copy |
|---------|------|
| Primary CTA | **"New Tab"** — opens a new tab (via the stock-window escape until GUI-02; the window opening is itself the visible behaviour, so no qualifier in the label). |
| Nav tooltips | **"Back"**, **"Forward"**, **"Reload"** — verb-only; unambiguous adjacent to the address pill. |
| Address placeholder | **"Search or enter address"** |
| Mode toggle segments | **"Coding"**, **"Browsing"**, **"Organising"** — exactly three shipped defaults, in this order. |
| Suggestion footer hint | **"Enter opens the address · Esc closes suggestions"** |
| Empty suggestions heading | **"No suggestions"** |
| Empty suggestions body | **"No matches for what you typed — press Enter to visit it as an address."** |
| Suggestions-unavailable error | **"Power Browser couldn't load suggestions. Press Enter to visit what you typed."** (provider failure degrades to a plain address commit; no Retry — there is nothing to retry that Enter does not already do) |
| Destructive confirmation | **None in this phase.** Back/forward/reload/new-tab/mode-switch are all non-destructive, and the tabs invariant (no tab closed, moved windows, or detached by a mode change) means no switch ever needs a confirmation. |
| Commit failure | **"Power Browser couldn't open that address. Press Enter to try again."** (a commit throw surfaces in-bar as a single dropdown row; Enter re-commits the typed text as the retry affordance, so the copy gate in 13-04 owns the identical string rather than standing alone) |

## Interaction Contract (GUI-06 + spike, net-new)

### Bar placement and order

Single chrome bar, full-bleed, 40px, immediately adjacent to the Theia tab
strip in the ratified Variant-A order: menubar → chrome bar → tab strip →
workarea → status bar. The bar is contributed to the top shell area, which
the shell stacks above the main dock owning the tab strip, and the
below-strip slot would need dock surgery, which is a Theia-core touch
forbidden by the never-fork-core hard rule, so below-strip stays out of
Variant A; exactly one bar, never two.
The status-bar tab-count chip (sketch pattern) asserts the tabs invariant on
every mode switch.

### Chrome bar composition (left to right)

Back, Forward, Reload | address pill (lock glyph + input + suggestions) |
New Tab | mode-toggle segmented control (Coding / Browsing / Organising).
No bookmarks strip, no per-tab close/mute, no browser menu — explicitly out.

### Address input and suggestions

- Typing filters history/bookmark suggestions; activating a suggestion (Enter
  or click) navigates. Dropdown is capped at **8 visible rows**, scrolls
  beyond; URI captions truncate with ellipsis (full URI in `title` tooltip).
- `Ctrl+L` (and `Cmd+L`) focuses the address input and selects its content.
  `Esc` dismisses the dropdown first, then restores the committed address on
  a second press. Arrow keys move the active descendant; Enter commits it.
- Committing a non-URL string treats it as a search-or-address per the
  existing tab-URI rules; the bar never invents a new addressability scheme.
- Navigation failures (DNS, refused frames) surface in the stock surfaces
  (`browser.xhtml` window / mini-browser stock states) — **do not author
  replacement error UI**, same precedent as 01-UI-SPEC GUI-02.

### Buttons and toggle

- Back/Forward are disabled (visually dimmed, tooltip retained) with no
  history in that direction; Reload is disabled with no navigable current
  tab. Disabled is styled, never removed — layout does not shift.
- New Tab uses the ratified candidate-A channel (`window.open(url, '_blank')`
  from the Theia frontend); a blocked popup surfaces the existing
  `browser-window-command` error path, not a new dialog.
- Mode toggle: clicking a segment selects it with immediate visual state
  (≤150ms). Shell-relocation consequences are Phase 14 (GUI-07) scope. The
  toggle must never close, move windows on, or detach any tab — the tabs
  invariant holds in every mode including under the Variant-A fallback.

### Strip-relocation spike verdict

- Green: a live tab strip moves Theia shell areas with zero Theia-core
  modifications (proven by the tree's core-diff check staying clean) and tab
  identity preserved (same registry URIs, selection intact) → Variant B strip
  work proceeds in Phase 14.
- Red: verdict recorded with the blocking cause; the strip stays top per
  Variant A and modes still ship in Phase 14. The fallback is a recorded
  decision, not a silent omission.
- The verdict lives in the phase SUMMARY/decision log; it is not a user-facing
  surface and carries no user-facing copy.

contracted in `## Color` (WCAG 2.4.7 / 2.4.11) — an accessibility contract,
not a probe state category.
