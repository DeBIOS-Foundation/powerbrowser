<objective>
Make the browser reachable (GUI-01) and keep it structurally reachable (GUI-04), by moving
startup-window selection out of a compiled define and into the command-line handler — after a spike
proves the move has no side effects, and after the developer ratifies it.

Purpose: per D-19 this is net-new work, not migration. Research disproved the earlier premise that a
browser toggle already existed in the source tree, three independent ways — the source project's own
hard rule that its sidecar is the only GUI, the shell document's own header comment, and the absence
of any web-scheme open handler or bridge package. Planning this phase as migrate-and-rename would
under-scope it by two features.

Research further established with high confidence that the compiled browser-chrome-URL define is not
merely "which window opens at startup" — upstream treats it as the identity test for "am I the main
browser window" in at least five places, so simply opening a real browser window under the current
architecture yields one with no address-bar focus and no in-window modal dialogs. The recommended
move is verified at all four upstream call sites but has never been executed, which is why D-20
requires a spike before the plan hard-commits. The move is also worth more than GUI-01: it strengthens
GUI-04 materially and reduces the shell patch toward a pure hook, pre-paying part of Phase 5.

Output: recorded spike findings, a ratified approach, and a working toggle with automated
window-count checks.
</objective>

- **The frontend-to-chrome channel is an open design question, not a settled one.** Research established that GUI-01 does not exist and recommended the command-line-handler mechanism, but it did not establish how a Theia command reaches chrome-privileged code in a release build with the privileged-JS development flag off. The UI-SPEC contracts a palette-reachable Theia command as the entry affordance. Spike observation 7 exists to close this, and the checkpoint ratifies the answer. If no channel works with the flag off, the fallback the checkpoint may select is a chrome-side keyboard shortcut owned by the shell window, which satisfies "a user can toggle" but not "one palette-reachable Theia command" — that divergence from the UI-SPEC must be recorded, not absorbed.
- **A second full Gecko build is unavoidable in this plan.** The compiled chrome-URL define changes, which is a tier-3 trigger, so both Task 1 and Task 3 pay roughly forty minutes. Task 3 reuses Task 1's working-tree diff rather than rediscovering it, which is why the spike's diff is preserved rather than discarded.
