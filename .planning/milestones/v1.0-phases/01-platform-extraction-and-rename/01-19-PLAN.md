<objective>
Close UAT gap G-01-25: the Theia shell's main window title bar shows the compact
identifier form of the product name instead of the ratified spaced display form.

The diagnosis is a single sufficient cause. `powerbrowser/shell/powerbrowser.xhtml`
hard-codes the chrome document's title as the identifier form, and that static
literal is what Gecko's AppWindow hands the window manager for the window's whole
lifetime: the shell JS never writes a title, the root element carries no
content-title-tracking attribute, and Theia's own correct `document.title` stays
inside the remote `<xul:browser>`. The loading layer's wordmark on the following
lines is the same leak in the same file. Theia's `applicationName` — the value the
UAT note suspected — is already correct and is not touched.

The reason no gate caught it is separable and is fixed as its own half:
`verify-branding-identity.mjs` asserts an enumerated surface set that does not
include the shell document, the residual scan hunts the originating product's
tokens and is blind to the new brand by design, and the one checker that DOES
enforce display-vs-identifier form — `verify-branding-preflight.mjs` section 6,
whose leak pattern already matches both offending literals exactly — simply never
reads the file.

Purpose: the title bar is the only OS-level identifier of which application owns
the window, and it currently disagrees with every other branding surface.
Output: two corrected literals, one stale checker expectation of the same class
corrected with them, and the shell's chrome markup added to the display-surface
scan by derivation so the next chrome document is covered the day it ships.
</objective>
