<objective>
**As a** downstream brand author, **I want to** leave every cosmetic key alone and be told exactly
which Power Browser defaults I inherited, **so that** I get a working build without transcribing a
manifest I did not write, and I can never inherit the parts of it that are Power Browser's identity.

The tracer proved one manifest key reaches one build surface. This plan adds the second layer: the
same file that carries Power Browser's brand becomes the defaults a downstream's file overlays, with
a mask that makes identity and legal keys un-inheritable and an echo that makes every inherited
cosmetic key visible.

Purpose: this is the half of CFG-04 that makes CFG-02 safe. Without the mask, "the root file is the
defaults" means a downstream that omits `[identity]` silently ships under Power Browser's mark —
the exact failure CFG-02 exists to prevent.

Output: a masker, a recursive merge that records provenance, a sorted per-key echo, and the
`--self-test` harness carrying the three fault cases that pin this behaviour.
</objective>

  <behavior>
    - Masking a defaults layer that carries a full `[identity]` table yields a layer with no
      `identity.` key at all, and no `legal.` key, and neither vendor key.
    - Merging a masked defaults layer under a downstream layer that omits `identity.binary_name`
      but sets `identity.app_basename` leaves `identity.binary_name` absent from the resolved
      config — the partial case behaves exactly like the total case.
    - Merging `{theia: {default_theme: "dark"}}` under `{}` yields `default_theme` of `"dark"` and
      records `theia.default_theme` as defaulted.
    - Merging `{theia: {default_theme: "dark"}}` under `{theia: {default_theme: "dark"}}` yields
      `"dark"` and records NOTHING as defaulted — an equal value is still a downstream-set value.
    - Merging a two-element default array under a one-element downstream array yields the
      one-element array, not three elements.
    - Merging a two-element default array under an empty downstream array yields the empty array.
    - Merging a layer carrying a `__proto__` key leaves `Object.prototype` with no new property.
  </behavior>
  <action>
    Turn the tracer's single-layer loader into the two-layer pipeline, keeping the pipeline order
    the tracer established: parse, unknown-key reject, mask, merge, validate.

    Loader. Change the loader to take two layer sources: a defaults source and an optional
    downstream source. In Phase 2 the defaults source is always the repo-root `configuration.toml`
    and the downstream source is absent in every production call — `PB_CONFIG_DIR` is Phase 7 work
    (CFG-05) and this plan does not add it. Wire the downstream parameter so the `--self-test`
    fixtures can supply one; that self-test is the merge's only Phase-2 coverage and the plan should
    say so rather than let a reader assume production exercises it. When no downstream layer is
    supplied, the merge still runs, with an empty downstream object, so there is exactly one merge
    code path and not a fast path plus a real path.

    Masker. Write `maskDefaults(defaultsLayer, schema)`, returning a new object with every key path
    the schema marks `required: true` removed. The schema's `required` flag IS the mask list —
    D-06's "one schema table consumed by both the masker and the validator" is satisfied by reading
    that flag rather than by writing a second list anywhere. Removal is per key path, not per table,
    so the behaviour is identical whether a downstream omits a whole table or omits three keys out
    of five. Leave a comment at the masker naming D-06 and stating what it prevents: without it, a
    downstream that omits identity keys silently inherits Power Browser's mark.

    Call the masker on the defaults layer OBJECT, before that object is an argument to the merge.
    Do not merge first and mask the result. The two orderings agree on the wholly-absent case and
    disagree on the partial case, and the partial case is the one that actually ships.

    Merge. Write `mergeLayers(masked, downstream)` returning `{ value, defaulted }` where
    `defaulted` is an array of dotted key paths whose resolved value came from the defaults layer.
    Rules: recursive and key-level at any depth; a leaf present in the downstream layer wins and is
    NOT recorded as defaulted, even when its value equals the default; a leaf absent from the
    downstream layer is taken from the defaults layer and its dotted path IS recorded; an array is
    a leaf — a downstream array replaces the entire default array and is never concatenated with
    it. Put a comment at the array branch naming D-07 and its purpose: arrays replace so that a
    downstream can DROP a default entry, which concatenation makes impossible. Every off-the-shelf
    deep-merge library concatenates by default, so a reviewer's instinct is to "fix" this; the
    comment and the pinned self-test case are what stop that.

    Build every accumulator with a null prototype and skip the three dangerous key names explicitly
    when copying keys. The unknown-key gate already rejects them because they are not in the schema,
    so this is belt and braces — but it is input validation at a trust boundary that becomes a real
    one in Phase 7, and it costs three lines.

    Return the defaulted-path array out of the merge rather than re-deriving it in a second
    traversal later. A second traversal is a second source of truth about the same fact and can
    disagree with the merge; the echo in Task 2 consumes this array directly.

    Validation runs on the merged result, unchanged from the tracer.
  </action>

  <action>
    Add the echo, then the harness that keeps it and the merge honest.

    Echo. After the merge and before emission, sort the merge's defaulted-path array
    lexicographically and print one `console.error` line per entry, carrying the dotted key path and
    the value. Render the value with JSON.stringify so a string is quoted, an empty string is
    visible, and an array renders compactly on one line. Print on EVERY run including `--check`, per
    D-08. Print nothing for keys the downstream set — the array from Task 1 already carries only the
    defaulted ones, so this is a sort and a loop, not a filter. Keep the echo on stderr so stdout
    stays free for the single PASS line, which is the shape every registered gate in this repo
    already uses. Dotted key paths are unique, so the sort has no ties and needs no tiebreaker; say
    so in a one-line comment rather than adding a comparator nobody can justify.

    Extend the PASS line to name both counts: how many files were written and how many defaults were
    applied. A count in the pass message is this repo's non-vacuity tell.

    Self-test harness. Replace the `--self-test` stub with the real harness, copying the structure
    of `verify-registry-shape.mjs` lines 179-249:

      1. A clean-baseline guard. Run the pipeline over the unmodified repo manifest first and bail
         with an explicit message if it is already red, because planted-fault results measured
         against an already-red baseline are meaningless.
      2. A frozen case table. Each case is a name, a fixture, and an `expect` string the failure
         output must contain.
      3. A mutation-landed guard per case. Assert the fixture actually differs from the clean
         manifest before running the check; a planted fault that changed nothing makes its case
         vacuous.
      4. Per case, require the failure output to CONTAIN the `expect` string, not merely to be
         non-empty.
      5. Print one `ok` line per passing case naming the case and the string it went red on, then a
         counted PASS line, then exit.

    Fixtures are TOML strings written into a `mkdtempSync` directory and removed in a `finally`,
    which is the established fixture idiom in this tree. Do not copy the whole repo tree; a TOML
    string per case is cheaper and the pipeline takes a path.

    Three cases in this plan; plan 02-06 appends the rest:

      - `whitespace identity value` — the downstream layer sets an identity key to a whitespace-only
        string. Expect the failure to name that key. This is D-10 and it is the case that proves an
        empty-ish value is not a value.
      - `partial identity table` — the downstream layer sets one identity key and omits another,
        while the defaults layer carries both. Expect the failure to name the OMITTED key. This is
        the case that goes red if someone moves the mask after the merge, and a self-test whose only
        identity fault is a wholly missing table cannot catch that.
      - `downstream array shorter than default` — the downstream layer declares a one-element
        variants array against a two-element default. Assert the resolved array has one element.
        This case goes red if someone changes array-replace to concatenation.

    Because two of these cases assert on a resolved value rather than on a failure string, give the
    case table a second assertion shape — a case may carry either an `expect` string the failures
    must contain, or a predicate over the resolved config. Keep both shapes in one table so the
    counted PASS line covers every case.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| downstream `configuration.toml` → merge | The layer this plan introduces. Operator-supplied in Phase 2 fixtures; an arbitrary external file in Phase 7 under `PB_CONFIG_DIR`. The merge is written for the Phase 7 shape. |
| defaults layer → resolved identity | The boundary the mask defends. Anything that crosses it becomes a value the downstream ships under. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-04 | Spoofing | `maskDefaults` and its call site | high | mitigate | The mask is applied to the defaults layer OBJECT before it is an argument to the merge, per D-06. Masking is per key path, so the partial case (some identity keys set, others omitted) behaves identically to the total case. A `partial identity table` self-test case pins the ordering and goes red if the mask is moved after the merge. |
| T-02-01 | Tampering / EoP | `mergeLayers` accumulators | high | mitigate | Unknown-key rejection already runs before the merge, so a dangerous key name never reaches an assignment. Canon note: prototype pollution is canon security material owned by `/gsd-secure-phase` and eslint security plugins; it is mitigated here structurally and not minted as a bespoke prohibition. |
| T-02-09 | Information Disclosure | the default echo | low | mitigate | The echo prints dotted key paths and manifest values only.
