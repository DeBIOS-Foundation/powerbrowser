<objective>
**As a** downstream brand author, **I want to** run one command and get every cheap build surface my
brand needs, and be told when what I have on disk no longer matches my manifest, **so that** I never
hand-edit a generated file and never build from a stale one.

The tracer proved one emitter reaches byte-identity. This plan expands to all five targets and adds
the freshness mode, so `configuration.toml` really is the only rebrand input for the surfaces
Phase 2 owns.

Purpose: this is where the byte-identity acceptance test becomes real for the whole target set, and
where the frozen target table stops being one entry and starts being the single declaration the
default run, `--check`, and the plan 02-05 gate all iterate.

Output: five emitted files matching five hand-written ones byte for byte, and a `--check` that is
honest about staleness, about absence, and about leftovers.
</objective>

    - After a clean generate, `--check` exits 0 and writes nothing.
    - Changing one byte in one file under `generated/` makes `--check` exit 1 naming exactly that
      path and not the other four.
    - Deleting `generated/` entirely makes `--check` exit 1 with a message that says the directory
      does not exist and names the command to run, rather than listing five stale paths.
    - Creating an extra file under `generated/` makes `--check` exit 1 naming that file.
    - `--check` leaves `generated/` byte-identical to how it found it, in every one of the above

    - `--check` prints the default echo, exactly as a default run does.

  <action>
    Replace the `--check` stub with the real mode. Its contract is: report whether what is on disk
    matches what the manifest would produce, and change nothing.

    Emit into a fresh `mkdtempSync` directory under the OS temp dir with a descriptive prefix, and
    remove it in a `finally`. A unique directory per invocation is what makes two concurrent
    invocations safe; a fixed temp path would have them overwrite each other's comparand. Never
    write into `generated/` in this mode — a check that regenerates in place and then compares
    cannot tell "was already fresh" from "I just made it fresh", and that is a non-discriminating
    instrument, not a gate.

    Three distinct outcomes, each with its own message:

      1. `generated/` does not exist. Exit 1 with a single line saying the directory is not there
         and naming the command that creates it. Do NOT list five stale paths — the tree has no
         defect, it just has not been generated yet, and this is the state every fresh clone and
         every CI run starts in because the directory is git-ignored. A five-path staleness report
         here reads as five problems and sends the reader looking for a drift that does not exist.

      2. One or more targets differ. Exit 1 listing every differing path, one indented line each,
         under a counted banner. Compare bytes; if a comparison fails, a line-level diff may be
         computed FOR THE MESSAGE ONLY. The assertion is byte-identity; a line differ is a reporting
         aid, not the check.

      3. A file exists under `generated/` that is not in the target table. Exit 1 naming it. Derive
         the actual file set with a recursive directory read and compare it to the target table's
         generated paths as a set equality, so this goes red on a leftover from a removed emitter as
         well as on a missing file. This closes the removal direction that a per-target loop alone
         cannot see.

    Add the non-vacuity guard: if the temporary emission produced zero files, fail with a message
    saying the comparison proves nothing, rather than reporting a clean diff of nothing against
    nothing. A comparison over an empty comparand is broken instrumentation and must not read as a
    pass.

    Print the default echo in this mode too, per D-08 — every applied default is echoed on every run
    including `--check`.

    Do not add a new CLI flag. `--check` and `--self-test` remain the only two arguments, and the
    reject-unknown-argument loop stays.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| manifest values → emitted file content | Manifest strings become bytes in a shell script and a desktop entry that a build and a desktop environment later read. |
| generator → filesystem write paths | Five paths under `generated/`, all literals in the frozen target table. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02 | Tampering | the writer and the frozen target table | medium | mitigate | Both the generated and the tracked path in every target entry are string literals. The variant contributes `objdir` and `branding_dir` as emitted CONTENT only — they appear in an `Icon=` line and a shell-default expansion, never in a path passed to mkdir or writeFileSync. An acceptance criterion asserts no entry builds a path from a manifest value. Canon note: path traversal is canon security material owned by `/gsd-secure-phase`; mitigated structurally here and not minted as a bespoke prohibition. |
| T-02-11 | Tampering | shell metacharacters in a manifest value reaching `configure.sh` | medium | mitigate | `MOZ_APP_DISPLAYNAME` is emitted inside double quotes and its value comes from `identity.display_name`, which is required and therefore always present. The three values reaching the mozconfig as bare arguments — app basename, distribution id, remoting name — are each regex-gated by the schema to characters that carry no shell meaning. A value that would need quoting cannot pass the gate. |
| T-02-12 | Tampering | a `--check` that regenerates in place | high | mitigate | `--check` emits only into a unique `mkdtempSync` directory removed in a `finally`, and an acceptance criterion asserts the sha256 set of `generated/` is unchanged across every check invocation. A non-vacuity guard fails a comparison whose comparand is empty rather than reporting it as clean. |
| T-02-13 | Information Disclosure | absolute host path in emitted desktop files | low | accept | The `Exec=` and `Icon=` lines carry the repo root by design (D-04); a desktop entry must name an absolute executable. It is emitted content in a git-ignored file, not user-facing error copy, so the no-internals copy rule does not reach it. Accepted with the rationale recorded. |
</threat_model>
