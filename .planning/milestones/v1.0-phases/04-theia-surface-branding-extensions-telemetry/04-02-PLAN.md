# Phase 4 Plan 02 — Declared extensions: manifest → pinned download → build bundle

**Goal:** A downstream declares Theia extensions in `configuration.toml`
(Open VSX id + version pin, or direct URL + sha256 pin); the generator
resolves them to exact download URLs, the build downloads and bundles them
into the sidecar, and an unpinned or unreachable entry fails the build
loudly naming the entry.

**Requirements covered:** EXT-01 (all of it)

**Wave:** 2 (blocked on 04-01 — touches `scripts/generate.mjs`,
`config-schema.json`, `verify-platform.sh` registry)

## Research conclusions this plan builds on (do not re-derive)

- `theia download:plugins` (`theia/node_modules/@theia/cli/lib/download-plugins.js`):
  reads the `theiaPlugins` map (id → URL string; non-string values ignored)
  in the application `package.json`; accepts `.vsix`/`.theia`/`.tar.gz`;
  5 attempts, 2s retry on 429/439/5xx; skips already-downloaded; throws
  `Errors downloading some plugins` unless `--ignore-errors`. No
  `theiaPlugins` block has ever existed in this tree.
- Pin is NOT hash-verifiable with stock tooling: extension-pack/dependency
  auto-resolution uses `findLatestCompatibleExtension` (latest, unpinned),
  and the OVSX API type (`ovsx-client/src/ovsx-types.ts`, `files:
  {download}`) exposes NO sha/hash field. Pin = exact versioned URL
  (`https://open-vsx.org/api/<ns>/<name>/<version>/file/<id>-<version>.vsix`)
  emitted at generate time + a post-download sha256 gate this plan adds.
- PROJECT.md Out of Scope: npm and local-path source kinds are v2
  (EXT-02). This plan implements Open VSX + direct URL only; reject anything
  else at generate time with a clear message.

## Tasks

### Task 1 — Schema `[[extensions]]` + URL-resolution emitter

1. `scripts/lib/config-schema.json`: add `extensions[].id` (required,
   `^[a-z0-9][a-z0-9.-]*\.[a-z0-9][a-z0-9.-]*$`-style namespaced form with
   `regex_help`/`regex_example`), `extensions[].source` (required, enum
   `openvsx`|`url` — enforce in `validate()`; the schema table has no enum
   mechanism, so add an explicit allowlist check beside the regex loop),
   `extensions[].version` (required when source is `openvsx`),
   `extensions[].url` (required when source is `url`, `https://` regex in
   the established style), `extensions[].sha256` (required, `^[0-9a-f]{64}$`).
   Arrays are leaves to the masker/merge (D-07): a downstream array REPLACES
   the default array — document that a downstream drops a default entry by
   restating the list without it.
2. `scripts/generate.mjs`: emitter builds the `theiaPlugins` map —
   `openvsx` → exact versioned file URL for the pinned version (no
   `findLatestCompatible` at any point in this pipeline: latest-resolution
   is the unpinned behavior this requirement forbids); `url` → URL
   verbatim. Emit to `generated/theia-plugins.json` (new TARGETS row, full
   `--check`/byte-identity coverage free via the frozen table), then
   surgically apply ONLY the `theiaPlugins` block to
   `theia/applications/browser/package.json` (Phase 2 copy-over precedent:
   block-level equality asserted, rest of file byte-identical — yarn owns
   that file's formatting). Unpinned entry (missing version/sha256, or
   source outside the v1 pair) fails generate naming the entry id.
3. FIXTURE_BASE + `--self-test`: new required keys added to fixtures; new
   planted faults — (a) entry without pin, (b) entry with `source = "npm"`,
   (c) sha256 of wrong shape — each must fail naming the entry.

**Verify:** `node scripts/generate.mjs --self-test` green with each new
fault observed red; fixture manifest with one `openvsx` + one `url` entry
produces a `theiaPlugins` block with two exact URLs and a byte-identical
remainder of `package.json`.

### Task 2 — Build wiring: download (loud) + sha256 gate + docs

1. Theia build path (`theia/package.json` scripts and/or
   `theia/applications/browser/package.json` `build`): run
   `theia download:plugins` WITHOUT `--ignore-errors` before the app
   bundle step (its absence today is why no block ever existed). Unreachable
   URL or non-200 status must fail the build with the entry id visible
   (stock behavior throws — assert it propagates, don't swallow it in a
   `|| true` or chained `;`).
2. New `scripts/verify-extension-pins.mjs` (or fold into the Task 1 check
   only if it stays honestly `--quick`: reads text + bytes off disk, no
   network, no browser): for each manifest entry, assert the downloaded
   artifact under `plugins/` (or `theiaPluginsDir`) has sha256 equal to the
   manifest pin; assert every emitted `theiaPlugins` URL is version-pinned
   (contains the pinned version segment — rejects a latest-floating URL);
   assert the `theiaPlugins` block in the application `package.json`
   block-equals `generated/theia-plugins.json`. `--self-test` with planted
   faults: corrupted byte in a downloaded vsix, unpinned URL, block drift —
   each goes red naming the entry. Tree-derived, set-equality style (no
   hand-kept expectation list per CLAUDE.md rule 2).
3. Document the pin-bootstrapping procedure (fetch vsix, `sha256sum`, paste
   into manifest) in the plan SUMMARY so 04-04/docs can carry it to
   `docs/REBRANDING.md` (Phase 6 writes that file — do NOT write it here).

**Verify:** point a fixture entry at an unreachable URL → build fails
loudly (observed, not asserted from code reading); flip one byte in a
downloaded artifact → pin check goes red naming the entry;
`--positive-control`-equivalent self-test rows all observed red pre-fix.

### Task 3 — Registry + preflight coexistence

1. `scripts/verify-platform.sh`: register new label(s) in the `--quick`
   table (network-free checks only — the download step itself is a build
   step, not a `--quick` check; the pin/block-equality check IS `--quick`).
2. `scripts/verify-branding-preflight.mjs`: if it asserts the application
   `package.json`'s exact shape anywhere, widen that assertion to tolerate
   the `theiaPlugins` block (derive tolerance from the generated file, not
   a literal). Keep its `--self-test` green.

**Verify:** `scripts/verify-platform.sh --quick` green on a tree with one
real pinned entry downloaded; `--only <new-label>` passes alone.

## Per-plan verification (must all go red when broken)

- Remove the pin from one entry → `node scripts/generate.mjs` exits
  nonzero naming the entry id (not a generic schema complaint).
- `theia download:plugins` against a fixture with a 404 URL → build step
  fails (proves `--ignore-errors` is absent and the failure propagates).
- Restore stock `package.json` (no `theiaPlugins`) while manifest declares
  entries → `--check`/pin check fails (proves stale-output detection, not
  just fresh-generate correctness).
