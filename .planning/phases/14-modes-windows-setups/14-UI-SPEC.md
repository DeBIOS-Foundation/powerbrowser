# Phase 14 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note.** This phase builds GUI-07 (modes) + GUI-09 (windows & setups):
coding / browsing / organising modes switchable from shipped defaults,
customizable, savable as data (never manifest flags); side panels slide per
mode; named setups save/restore geometry + tab placement + mode; dependent
windows host tab content only, never a second IDE frame; core-close kills the
session, relaunch restores. Never fork/patch Theia core; never modify Gecko
outside the 2 hook-only patches.

**Binding constraint (13-01 spike verdict RED).** The tab strip **STAYS TOP in
all modes** per the Variant-A fallback. Modes reshape panels and visibility;
no Phase-14 surface relocates the strip, and no contract below may be read as
requiring relocation. Sketch 002-B intent is bounded accordingly: mode
differences are panel visibility + main-area view, strip position fixed.
Phase-15 organising CANVAS is out of scope — this phase contracts only the
mode switch into an organising placeholder slot, not the canvas.

**Inherits from 13-UI-SPEC** (do not contradict): design system `none`,
spacing ramp, typography delegation (3 sizes / 2 weights), color tokens,
60/30/10 split, focus idiom, motion baseline, copy rules (product named
"Power Browser", plain language, real on-screen next step, no internal
identifiers), "chrome bar" naming, chrome-bar order (menubar → tab strip →
chrome bar → workarea → status bar), toggle segments Coding / Browsing /
Organising, tabs invariant asserted by the status-bar chip. This spec states
only what is net-new or extended; unmentioned 13 contracts stand unchanged.

dependents read as the same product.

## Spacing Scale

Declared values (all multiples of 4). Sketch `--space-*` ramp adopted verbatim
from 13-UI-SPEC; `12px` is a declared step, not an exception.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, setup-row text gap |
| sm | 8px | Panel-internal gaps, dialog content gaps |
| md-gap | 12px | Setup/mode row horizontal padding, dialog padding |
| md | 16px | Dialog vertical padding, default element spacing |
| lg | 24px | Placeholder vertical rhythm (heading ↔ body ↔ button) |
| xl | 32px | Setup/mode row min-height, mode segment hit area (32×32 carried) |
| 2xl | 48px | Not used in Phase 14 (reserved) |
| 3xl | 64px | Not used in Phase 14 (reserved) |

Fixed geometry (prescriptive): mode and setup list rows `min-height: 32px`,
`radius-sm` (4px). Save dialogs use the Theia stock dialog frame with content
padding 12px; the name input is 32px tall. Mode segments keep the shipped
96px fixed width. Hairline borders `1px var(--color-border)` throughout.
Placeholder slot content max-width 480px, centred in the main area.

Exceptions:

| Exception | Value | Why it stands |
|-----------|-------|---------------|
| Dependent-window geometry (position, size) | OS pixels, not scale | Window frames are owned by the window manager; setups record the rect verbatim and restore it verbatim |
| `radius-full: 9999px` | non-scale | Pill token from the locked sketch theme; unchanged from Phase 13 |
| Panel slide distance | Theia region width (stock) | The slide animates the stock region's own width; the contract fixes duration/easing only (see Motion) |

## Typography

Theia side is delegated — the table below binds the delegation to exact
rendered sizes (3 sizes, 2 weights). No `font-size` / `font-weight` literal
may appear in `@powerbrowser/*` that is not one of these three sizes.

| Role | Size | Weight | Line Height | Applies to |
|------|------|--------|-------------|------------|
| Body | 14px | 400 | 1.5 | Setup/mode row names, dialog body, placeholder body, dependent titles |
| Label | 13px | 400 (inactive) / 600 (active-selected) | 1.4 | Mode-toggle segments, setup-row meta line, dialog buttons (Theia stock) |
| Caption | 12px | 400 | 1.5 | Setup-row meta (mode · windows · tabs), dialog hints, placeholder footnote |

600 (semibold) is reserved for exactly two selection states: the **active
mode-toggle segment** (carried from Phase 13) and the **current-setup /
current-mode marked row** in the setups/mode lists. Nothing else in this phase
sets 600. There are no headings above 14px in this phase — the placeholder
heading renders at 14px/600, never display type; dialogs use the Theia stock
title idiom.

## Color

Locked sketch theme (`sources/themes/default.css`), genuine 60/30/10 split by
painted area. Identical tokens to Phase 13; only the usage rows grow.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1c1b22` (`--color-bg`) | Window / workarea background, dependent-window background |
| Secondary (30%) | `#2b2a33` (`--color-surface`) fills, `#35343f` (`--color-surface-raised`) hover, `#3f3e4a` (`--color-border`) hairlines | Setup/mode rows, dialogs (stock frame over surface), placeholder panel, hover raises |
| Text | `#fbfbfe` (`--color-text`) primary ink, `#9a99a8` (`--color-text-muted`) secondary ink | Names, meta lines, placeholder copy, inactive segments |
| Accent (10%) | `#00a6f5` (`--color-primary`), hover `#0090d4` | See reserved-for list below — nothing else |
| Success | `#8ad38a` | Lock glyph only (carried; no new success surface) |
| Destructive | `#ff848b` (`--color-danger` from the locked theme) | **Delete Setup confirmation only** — confirm button + dialog warning marker |

**Accent reserved for — exhaustive list (items 1–3 carried from Phase 13, item 4 net-new):**

1. Address-pill focus border/ring.
2. Active mode-toggle segment ink (never fill) + 600.
3. Keyboard-highlighted suggestion row wash.
4. Current-setup / current-mode selected-row marker — accent-ink check glyph
   (or a 2px left rule; planner picks one, never both) plus the reserved 600
   on the row name.

Nothing else. Accent must never be used as a general fill, the placeholder
"Back to Browsing" control is a Theia stock button (theme-owned, not this
contract's accent), and no second brand hue may be introduced.

### Contrast

Unchanged pairings from Phase 13 (`#fbfbfe` on `#1c1b22` ≈ 16:1;
`#fbfbfe` on `#2b2a33` ≈ 13:1; `#9a99a8` on `#2b2a33` ≈ 5:1 — AA for
secondary text and captions). Muted ink must never be the sole carrier of the
selected-row state (600 + accent marker carry it too). `#ff848b` on
`#2b2a33` ≈ 5:1 — the Delete control pairs destructive ink on surface with
its explicit label; colour is never the sole carrier (label + confirmation
step carry it).

### Focus

Every Phase-14 control (mode menu items, setup rows via roving selection,
dialog inputs and buttons, placeholder button, dependent-window close)
shows a visible focus indicator:
`outline: 2px solid var(--color-primary); outline-offset: 2px`
(WCAG 2.4.7 / 2.4.11, same idiom as 13-UI-SPEC).

### Motion

Baseline `transition: all 0.15s ease` on every interactive element
(sketch-locked, carried). Side panels **slide** per mode switch: duration
≤200ms, same easing; `prefers-reduced-motion` renders the switch instantly
with no slide. Mode-switch visual state (toggle segment) applies ≤150ms
(carried). Tabs never unmount during a switch — there is no tab loading state
on mode change. Dependent-window open/close uses the stock window-manager
animation; no custom window animation is authored.

## Copywriting Contract

Product rules inherited from 13-UI-SPEC and CLAUDE.md: every user-facing
string names the product as **"Power Browser"** where a product name is
needed, states the problem in plain language, ends with a next step that is
a real affordance on screen, and carries **no internal identifier** (no pref
key, sentinel, port, URI-scheme internals, table name, or raw exception text).
Naming is fixed: **"chrome bar"**, mode names **"Coding"**, **"Browsing"**,
**"Organising"** (exactly three shipped defaults, in this order).

| Element | Copy |
|---------|------|
| Primary CTA (setups) | **"Save Setup"** — dialog confirm; saves windows, tabs, and mode under the typed name |
| Primary CTA (modes) | **"Save as Mode"** — saves the current panel layout as a custom mode |
| Setup dialog title | **"Save Setup"** |
| Setup name placeholder | **"Setup name"** |
| Empty setup name error | **"Give the setup a name — type a name and choose Save Setup."** |
| Duplicate setup name error | **"A setup with this name already exists. Choose a different name, or delete the existing setup first."** |
| Empty setups heading | **"No saved setups"** |
| Empty setups body | **"Save the current windows, tabs, and mode as a setup to restore them later — choose Save Setup."** |
| Setup row meta | **"{Mode} · {N} window(s) · {M} tab(s)"** — counts from stored data, singular/plural exact |
| Restore-failure error | **"Power Browser couldn't restore this setup. Your current windows and tabs are unchanged — try again, or delete the setup and save a new one."** |
| Corrupt-mode fallback notice | **"Power Browser couldn't load the "{name}" mode. Browsing is shown instead."** (status-bar flash; custom data falls back to the shipped Browsing default, never a blank shell) |
| Mode saved confirmation | **"Mode "{name}" saved."** (status-bar flash) |
| Setup saved confirmation | **"Setup "{name}" saved."** (status-bar flash) |
| Organising placeholder heading | **"Organising arrives next"** |
| Organising placeholder body | **"The freeform canvas for arranging tabs lands in the next update — your tabs stay exactly where they left them."** |
| Organising placeholder button | **"Back to Browsing"** — selects the Browsing mode |
| Dependent tab-closed state heading | **"This tab is closed"** |
| Dependent tab-closed state body | **"The tab shown in this window was closed. Close this window to return to Power Browser."** |
| Dependent tab-closed button | **"Close Window"** — closes only that dependent window |
| Destructive confirmation | **Delete Setup**: title **"Delete Setup"**, body **"Delete "{name}"? You can't undo this."**, buttons **"Delete"** / **"Cancel"** (Delete in destructive ink). This is the ONLY destructive action in the phase. |
| Core-close confirmation | **None — deliberately.** Closing the core window closes dependents with it and ends the session with no dialog; guaranteed restore on relaunch is the safety net, so a confirmation would tax every close for a recoverable event. |

## Interaction Contract (GUI-07 + GUI-09, net-new)

### Modes reshape panels and visibility — the strip never moves

Per-mode shell map (prescriptive, RED-bounded). The tab strip stays top in
every mode; only side-panel visibility and the main-area view change:

| Mode | Left panel | Right panel | Bottom panel | Main area |
|------|-----------|-------------|--------------|-----------|
| Browsing (launch default) | hidden | hidden | hidden | Tab content, maximised |
| Coding | visible (Explorer) | per saved layout | visible | Tab content beside visible panels |
| Organising | hidden | hidden | hidden | Organising placeholder slot (see below) |

- Switching selects the toggle segment with immediate visual state (≤150ms);
  panels slide (≤200ms, instant under reduced motion). Content tabs never
  unmount, close, move windows, or detach — the status-bar tab-count chip
  re-asserts the invariant on every switch (carried pattern).
- Custom modes save the current panel visibility/layout as data with shipped
  defaults behind them; a custom mode never alters a shipped default in place.
  No `[features]`/`[modes]` manifest flag exists anywhere in this contract.
- A mode switch is never destructive and never needs confirmation.

### Organising placeholder slot (Phase-15 canvas explicitly out)

- The Organising main area renders one centred static panel (max-width
  480px): the contracted heading, body, and a single Theia stock
  "Back to Browsing" button. No canvas, no tree, no drag surface, no zoom —
  any such surface is a Phase-15 scope violation.
- The placeholder paints synchronously with the mode switch (no spinner, no
  skeleton). It carries no failure state.

### Dependent windows (tab content only, never a second IDE frame)

- A dependent window hosts exactly one tab's content view with that tab's
  title in its title area. It contains: **no** chrome bar, **no** mode
  toggle, **no** side panels, **no** status bar, **no** tab strip. Address
  input, mode switching, and setup management live in the core window only.
- Opening a dependent never duplicates IDE state and never moves the tab out
  of the core model — the tab remains a core-model tab (tabs invariant holds
  across windows). Closing a dependent returns focus to the core window and
  destroys nothing.
- If the hosted tab is closed elsewhere, the dependent renders the
  contracted "This tab is closed" state with its "Close Window" button —
  never a blank frame, never a second copy of the tab.
- Closing the core window closes all dependents with it and ends the
  session — no confirmation (contracted above). The next launch restores the
  last setup automatically. Relaunch failure surfaces through the existing
  shell error path (01-UI-SPEC) — no replacement error UI is authored here.

### Named setups (geometry + tab placement + mode)

- **Save:** dialog with one name field (cap 60 characters) + Save/Cancel.
  Empty commits render the empty-name error; duplicates render the
  duplicate-name error; success flashes the saved confirmation and marks the
  new row current. Overwriting an existing name is not offered — delete first.
- **List:** rows show the setup name (14px) over the meta line
  ("{Mode} · {N} window(s) · {M} tab(s)", 12px muted). The current setup
  carries the accent marker + 600 name. Zero setups render the contracted
  empty copy. Beyond the visible cap the list scrolls internally; it never
  grows its host. Host widget (quick-pick, menu, or view) is the planner's
  call — row contract here binds any host.
- **Restore:** applies geometry verbatim, tab placement, and mode. Tabs that
  no longer exist are dropped; if zero tabs restore, the restore still
  completes (geometry + mode applied) and flashes the restore-failure error
  wording variant naming the dropped tabs as "some tabs no longer exist" —
  the row is never left half-applied with no explanation. Failure leaves
  current windows and tabs untouched (contracted error copy).
- **Delete:** the ONLY destructive action — contracted confirmation, no
  undo. Deleting the current setup clears the current marker; it changes
  nothing on screen.
- Setup and custom-mode names truncate with ellipsis at their row/segment
  width (full name in `title` tooltip). This resolves 13-UI-SPEC's unresolved
  custom-mode-name row: segments keep the fixed 96px width, ellipsis inside.
