### Motion (the only visual property that may change, G-32)

At HEAD, stock `ApplicationShell.DEFAULT_OPTIONS` sets `expandDuration: 0` on the left, right
and bottom panels (`application-shell.js:2080-2092`), and the tree's
`rebind(ApplicationShellOptions)` in `chrome-bar-frontend-module.ts:53-57` overrides only
`expandThreshold`. Every side panel therefore opens and closes **instantly** on a mode switch
today. Collapse is a class flip with no duration path (`side-panel-handler.js:333-342`,
`refresh()` adds the collapsed class). Outside Coding the left and right containers are also
hidden outright by `applyStripHome()` (`chrome-bar-widget.tsx`, `container.setHidden(!ideDress)`).

What the user sees under each G-32 option (Chris decides at the blocking checkpoint, see R3):

| Option | Entering Coding (panels open) | Leaving Coding (panels close) | Reduced motion | 14-UI-SPEC after |
|--------|-------------------------------|-------------------------------|----------------|------------------|
| a. Instant, spec amended | Explorer and bottom panel appear at full size in one frame | Panels disappear in one frame | Identical (already instant) | Motion and Interaction lines say panels switch instantly; slide-distance exception struck; UI Considerations loading row restated |
| b. Slide on open only | Left, right and bottom panels grow from zero to their size over the chosen `expandDuration` (≤ 200 ms), stock easing | Instant, as today | `expandDuration` is 0 when `prefers-reduced-motion: reduce` matches at startup; a change of the OS setting applies at the next reload | Motion says "panels slide open (≤ 200 ms) and close instantly; reduced motion opens them instantly" |
| c. Slide both ways | As option b | Panels shrink to zero over the same duration before hiding | As option b, both directions | Motion keeps "slide per mode switch, ≤ 200 ms", reduced-motion fallback kept |

Facts the decision brief carries for options b and c:

- The stock animation runs only when the application state is `ready`
  (`side-panel-handler.js:500`, `application-shell.js:753`). The launch-mode switch can land
  before `ready`, so a cold launch into Coding opens instantly under every option.
- Option b is a value in the existing partial rebind; no new widget, no CSS on Theia's panel
  containers. The rebind's comment ("`expandDuration` … keep their framework values") is
  rewritten in the same commit.
- Option c has no stock path for collapse. It needs authored behaviour: either animating the
  panel size to zero through the shell's public side-panel API before `collapse()`, or a width
  transition on Theia's side-panel containers. The latter works against Lumino's computed
  layout. In both, the left and right containers are already hidden by `applyStripHome()` when
  leaving Coding, so that hide must wait for the slide to finish or the slide is never seen.
- Tabs never unmount on a switch under any option, so there is no tab loading state
  (14-UI-SPEC, unchanged).

Baseline `transition: all 0.15s ease` on interactive elements and the ≤ 150 ms toggle-segment
state are unchanged under every option.

## Interaction Contract

### G-23 / MODE-02 — name cap while typing (Chris: "Cut at 60 while typing")

Applies to exactly two inputs: **Save as Mode** (`ModeService.saveCurrentAsMode`) and **Save
Setup** (`SetupsService.saveCurrentAsSetup`).

- The field never shows more than 60 characters. Typing past 60 adds nothing; pasting a longer
  string leaves its first 60 characters (A1, A2).
- No message, counter or colour change accompanies the cut (A4).
- Enter commits, Esc cancels, exactly as today. Empty and duplicate names behave as today with
  the existing copy. The commit-time trim and slice remain (A3).
- `MODE_NAME_MAX` and `SETUP_NAME_MAX` (both 60) are the only cap values; the listener reads
  them, not a literal.
- Mechanism: `QuickInputService.input()` takes `InputOptions`, which has no length option
  (`quick-pick-service.d.ts:187-199`). The stock path is `createInputBox()` with an
  `onDidChangeValue` handler that sets `box.value` back to the first `MAX` characters, plus
  `onDidAccept` and `onDidHide` to resolve the answer. The planner may share one small helper
  between the two services if both live in `@powerbrowser/modes`; they do.

The 14-UI-SPEC text after the change (planner keeps this meaning; exact wording is planner's):

- Named setups, **Save**: "A quick input with one name field, capped at 60 characters while
  typing; pasted text is cut to its first 60 characters. Enter saves, Esc cancels." (replaces
  ":316 dialog with one name field (cap 60 characters) + Save/Cancel").
- The same rule stated once for **Save as Mode** in the custom-modes bullet.
- UI Considerations row `long-text | E2 name input`: "Input holds at most 60 characters; typed
  and pasted overflow is cut at the cap while typing, before commit."
