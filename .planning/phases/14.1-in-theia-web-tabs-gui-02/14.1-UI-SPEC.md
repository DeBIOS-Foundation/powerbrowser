# Phase 14.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note.** This phase builds GUI-02: the chrome-bar "+" opens a web page tab
inside the Theia shell's own main-area tab strip. The page is rendered by a
chrome-owned `<xul:browser>` overlay kept aligned with a Theia placeholder widget
through a two-way bridge (Theia sends geometry, visibility, close; chrome sends URL,
title, loading state, back/forward availability). The tab survives every mode switch;
every tab has a URI via `TabUriRegistry` (web tabs use their page URL); the address
pill shows and navigates the active tab; back/forward/reload act on it; each web tab
writes its uri/url/title row to the chrome-side tab store. It replaces the
stock-window escape for "+", address commits, and suggestion activation. Never fork
or patch Theia core; never modify Gecko outside the patch stack; no new dependencies.

**Auto mode.** No CONTEXT.md exists and no user was available. Locked inputs:
REQUIREMENTS.md GUI-02, ROADMAP Phase 14.1 goal + 5 success criteria, the sketch
findings, and every token / copy / placement decision in 13-UI-SPEC and 14-UI-SPEC.
Everything else was decided for the most consistent option and is listed in
`## Assumptions (auto mode)` below so the planner and Chris can see what was chosen.

**Inherits from 13-UI-SPEC and 14-UI-SPEC** (do not contradict): design system
`none`, spacing ramp, typography delegation (3 sizes / 2 weights), color tokens,
60/30/10 split, focus idiom, motion baseline (panel slide ≤200ms, instant under
reduced motion), copy rules (product named "Power Browser", plain language, real
on-screen next step, no internal identifiers), "chrome bar" naming, chrome-bar order
(menubar → chrome bar → tab strip → workarea → status bar), disabled-not-removed nav
buttons, the per-mode shell map, "content tabs never unmount, close, move windows,
or detach", and the dependent-window rules. This spec states only what is net-new or
extended; unmentioned contracts stand unchanged.

**Supersessions (explicit):**

- 13-UI-SPEC `## Copywriting Contract`, Primary CTA row: the qualifier "via the
  stock-window escape until GUI-02" is retired. "New Tab" now opens an in-shell web
  tab. The label is unchanged.
- 13-UI-SPEC `### Buttons and toggle`, "New Tab uses the ratified candidate-A
  channel (`window.open`)": retired for "+", address commits, and suggestion
  activation. The candidate-A channel survives only behind the palette command
  "Open Browser Window" (GUI-01, unchanged).
- 13-UI-SPEC `### Address input and suggestions`, "Navigation failures surface in
  the stock surfaces (`browser.xhtml` window / mini-browser stock states)": the
  stock surface is now Gecko's own error page rendered inside the overlay (see
  Failure surfaces). The rule "do not author replacement error UI" for page-load
  failures stands.
- 01-UI-SPEC `### GUI-02 — web pages as Theia tabs` (mini-browser iframe, "Open in
  browser window" escape CTA): superseded in full by the 2026-09-06 requirement.
  None of it is implemented; the escape CTA does not exist.
- 14-UI-SPEC `## Provenance` "Deferred: in-Theia web tabs (GUI-02)": no longer
  deferred.

## Spacing Scale

Declared values (all multiples of 4). Sketch `--space-*` ramp adopted verbatim from
13-UI-SPEC; `12px` is a declared step, not an exception.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (carried); gap between the tab icon and label is Theia stock |
| sm | 8px | Bar-internal gaps (carried) |
| md-gap | 12px | Address-pill horizontal padding (carried) |
| md | 16px | Placeholder-state text block padding (empty state, lost-view state) |
| lg | 24px | Not used in Phase 14.1 (reserved) |
| xl | 32px | Nav button hit area, pill height (carried) |
| 2xl | 48px | Not used in Phase 14.1 (reserved) |
| 3xl | 64px | Not used in Phase 14.1 (reserved) |

Fixed geometry (prescriptive):

- The **placeholder widget fills its Lumino-assigned bounds** with zero padding,
  zero border, zero margin. The overlay copies `getBoundingClientRect()` of the
  placeholder node verbatim (CSS px, rounded to integers) — any padding here would
  offset the page.
- The **overlay `<xul:browser>`** carries `border: none`, no radius, no shadow. It is
  the page, not a card.
- The **placeholder-state text block** (empty state, lost-view state) is centred in
  the placeholder, `max-width: 480px` (carried from 14-UI-SPEC's placeholder slot),
  padding 16px, text-align centre.
- **Tab strip geometry** is Theia stock (tab height, icon slot, close glyph, overflow
  scrolling). Nothing in this phase resizes or restyles the strip.

Exceptions:

| Exception | Value | Why it stands |
|-----------|-------|---------------|
| Overlay rect | Whatever Lumino gives the placeholder, in CSS px | The overlay mirrors layout it does not own; the numbers are measured, never chosen. Alignment tolerance is **≤1 CSS px** on all four edges (the live check's assertion). |
| Theia tab-strip geometry | Theia stock | The web tab is a stock main-area title; changing strip metrics would be a Theia-core touch. |
| `radius-full: 9999px` | non-scale | Pill token, unchanged from Phase 13. |

## Typography

Theia side is delegated — the table binds the delegation to exact rendered sizes
(3 sizes, 2 weights, identical to Phases 13 and 14). No `font-size` / `font-weight`
literal may appear in `@powerbrowser/*` that is not one of these three sizes.

| Role | Size | Weight | Line Height | Applies to |
|------|------|--------|-------------|------------|
| Body | 14px | 400 | 1.5 | Address input text (carried); placeholder empty-state line; placeholder lost-view line |
| Label | 13px | 400 (inactive) / 600 (active) | 1.4 | Mode-toggle segments, tab-count chip (carried); the web tab's strip label is **Theia stock** (its own size) and is not restyled |
| Caption | 12px | 400 | 1.5 | Suggestion URI captions (carried); the web tab's tooltip (`title.caption`) is Theia stock |

600 (semibold) keeps exactly the carried reserved uses (active mode-toggle segment;
current-setup / current-mode marked row). **This phase adds no 600 use.** The
placeholder states are single 14px/400 lines with no heading. There are no headings
or display type in this phase.

The tab label is `title.label` on a stock Theia title; Theia decides its size, weight,
and truncation. Web pages inside the overlay set their own typography and are outside
this contract.

## Color

Locked sketch theme (`sources/themes/default.css`), genuine 60/30/10 split by painted
area. Identical tokens to Phases 13 and 14; only usage rows grow.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1c1b22` (`--color-bg`) | Window / workarea background; **the placeholder surface** — what the tab body shows when the overlay is hidden, not yet attached, or the tab has no page |
| Secondary (30%) | `#2b2a33` (`--color-surface`) fills, `#35343f` (`--color-surface-raised`) hover, `#3f3e4a` (`--color-border`) hairlines | Chrome bar, pill, dropdown (carried); tab strip is Theia-themed stock |
| Text | `#fbfbfe` (`--color-text`) primary ink, `#9a99a8` (`--color-text-muted`) secondary ink | Pill text (carried); placeholder empty-state line in **muted** ink; placeholder lost-view line in **primary** ink |
| Accent (10%) | `#00a6f5` (`--color-primary`), hover `#0090d4` | See reserved-for list — nothing else |
| Success | `#8ad38a` | Lock glyph in the pill when the shown address starts with `https://` (carried rule, unchanged) |
| Destructive | **none declared** | No destructive action exists in this phase (closing a web tab is stock tab close, no confirmation) |

**Accent reserved for — exhaustive list (items 1–4 carried; nothing net-new):**

1. Address-pill focus border/ring.
2. Active mode-toggle segment ink (never fill) + 600.
3. Keyboard-highlighted suggestion row wash.
4. Current-setup / current-mode selected-row marker.

Nothing else. The web tab's strip icon, spinning loading icon, and close glyph take
Theia's stock tab ink (theme-owned, not this contract's accent). The overlay itself
paints the page and carries no colour of ours. No second brand hue may be introduced.

### Contrast

Unchanged pairings from Phase 13: `#fbfbfe` on `#1c1b22` ≈ 16:1 (AAA — the
lost-view line); `#9a99a8` on `#1c1b22` ≈ 6.2:1 (AA — the empty-state line, secondary
text on the dominant surface). Muted ink is never the sole carrier of any state in
this phase: the empty state is also signalled by the empty pill with its placeholder,
and the lost-view state by primary ink plus the enabled Reload control.

### Focus

Every net-new focusable (the placeholder node) shows the carried indicator when
focused via keyboard: `outline: 2px solid var(--color-primary); outline-offset: -2px`
(inset, because the placeholder fills its bounds and an outset ring would be clipped
by the dock). Chrome-bar controls keep their carried `outline-offset: 2px`. Focus
inside the page is the page's own (Gecko stock) and is not restyled.

### Motion

Baseline `transition: all 0.15s ease` on interactive bar elements (carried).
**The overlay has no transition of its own** — its rect is applied synchronously from
each geometry message so it can track the ≤200ms panel slide frame by frame; a
transition on the overlay would lag the placeholder. Visibility changes (hide/show)
are instantaneous, no fade. The loading icon uses the stock `codicon-modifier-spin`
animation; under `prefers-reduced-motion` the icon is shown static (`codicon-loading`
without the spin modifier).

## Copywriting Contract

Product rules inherited from 13/14-UI-SPEC and CLAUDE.md: every user-facing string
names the product as **"Power Browser"** where a product name is needed, states the
problem in plain language, ends with a next step that is a real affordance on
screen, and carries **no internal identifier** (no pref key, sentinel, port, URI-scheme
internal such as `about:blank`, tab id, message kind, command id, or raw exception
text). Naming is fixed: **"chrome bar"**; **"New Tab"**; **"tab"** (never "web tab" in
copy — the qualifier is a planning term).

| Element | Copy |
|---------|------|
| Primary CTA | **"New Tab"** (carried label, retired qualifier) — opens an empty tab in the main-area strip and focuses the address pill. |
| Nav tooltips | **"Back"**, **"Forward"**, **"Reload"** — carried verbatim; now enabled by the active tab (see Interaction Contract). No "Stop" label is introduced. |
| Address placeholder | **"Search or enter address"** — carried verbatim; shown whenever the pill value is empty (new empty tab, or a non-web tab with no registry URI). |
| New-tab title (strip label) | **"New Tab"** — the label of a tab that has no page yet. Also its tooltip (`title.caption`). |
| Loading title fallback | The page **URL** (full, as reported by chrome) until the first title arrives; a page that never sets a title keeps the URL as its label. Never a blank label. |
| Empty state (tab body, no page) | **"Type an address above to get started."** — one line, muted ink, centred. Shown only while the tab has no page. |
| Lost-view state (tab body) | **"Power Browser can't show this page right now. Choose Reload to try again, or close this tab."** — one line, primary ink, centred. Shown when chrome refused or never acknowledged the tab's open, or reports the tab as unknown after a chrome-side restart. Reload (chrome bar, enabled) and the tab's stock close glyph are the two named affordances. |
| Commit failure (in-bar row) | **"Power Browser couldn't open that address. Press Enter to try again."** — carried verbatim from 13-UI-SPEC; now also the surface for a navigate/open request the chrome side refused or did not acknowledge. |
| Page-load failure | **No copy authored.** Gecko's stock error page (network error, blocked, certificate) renders inside the overlay with its own "Try Again"; the pill keeps the attempted address. Same precedent as 13-UI-SPEC: do not author replacement error UI. |
| Dependent-window move | **No copy.** The move is not offered for a web tab (see Interaction Contract), so there is nothing to refuse and no message to write. |
| Destructive confirmation | **None in this phase.** Closing a tab is stock, unconfirmed tab close; navigation, mode switches, and "+" are non-destructive. |

Every string above is a React text node or a `title`/`aria-label` attribute value,
never markup. Page titles and URLs flow into `title.label`, `title.caption`, the
placeholder `aria-label`, and the pill `value` as text only.

## Interaction Contract (GUI-02, net-new)

### The web tab in the main-area tab strip

- **Creation.** "+" (chrome bar button or `New Tab` command), a committed address
  when the active tab is not a web tab, and an activated suggestion when the active
  tab is not a web tab each add **one** stock main-area title to the strip and
  activate it. No OS window opens for any of the three.
- **Label.** Page title when the page has one; otherwise the page URL; **"New Tab"**
  while the tab has no page. Updates on every title change chrome reports. Theia
  stock truncation applies (ellipsis at the strip's tab width; full label in the
  stock tooltip).
- **Tooltip (`title.caption`).** The page URL; **"New Tab"** for a tab with no page.
- **Icon.** A fixed `codicon codicon-globe` for every web tab. **While loading**
  the icon is `codicon codicon-loading codicon-modifier-spin` (static
  `codicon-loading` under reduced motion); it reverts to `globe` when loading stops.
  The spinning icon is the **only** loading indicator this phase — no progress bar,
  no pill spinner, no Reload→Stop swap. No favicon transport (deferred; see
  Assumptions).
- **Close.** Stock Theia close: the title's close glyph, the stock tab context menu
  "Close", and the stock `core.close` keybinding (Alt+W in the browser target).
  Closing a web tab sends `close` to chrome, which drops the overlay and removes the
  tab's store row. No confirmation.
- **Tab body when the overlay is hidden or not yet attached.** The placeholder
  paints `--color-bg` (#1c1b22) edge to edge — a flat surface, no spinner, no
  skeleton, no text — **except** in the two text states below.
- **Tab body, no page (bare "+").** The placeholder paints the empty-state line on
  `--color-bg`; the overlay is **not shown** for a tab that has no page (the frontend
  publishes `visible: false` while the tab's URL is the empty-page URL), so the dark
  surface, not a white blank document, is what the user sees. The pill is empty with
  its placeholder and receives focus.
- **Tab body, lost view.** The placeholder paints the lost-view line on
  `--color-bg`. Reload re-issues the open and, on success, the page returns and the
  line disappears; close removes the tab.
- **Tab body, populated.** The overlay covers the placeholder exactly (≤1 CSS px on
  every edge) and the page fills it. Nothing of ours is drawn over or around the page.

### The address pill, bound to the active tab

- **Value.** On every current-widget change and every state push for the current
  tab, the pill value becomes the active tab's address: for a web tab, its current
  page URL (canonical form as reported by chrome — `example.com` becomes
  `https://example.com/` on the first location change); for any other tab, its
  `TabUriRegistry` URI string (`view:`, `settings:`, `terminal:`, editor resource);
  **empty** when the tab has no registry URI or no page. A tab with no page shows an
  empty pill (never the empty-page URL).
- **While the user is typing** (input focused), the pill is **not** overwritten by
  tab changes or state pushes; the committed address is restored by the carried
  two-stage Esc.
- **On commit** the pill shows the typed/normalised text immediately (carried), then
  the canonical URL when chrome reports the location change. During the in-flight
  navigation the pill shows the target URL — the pill has no separate loading state;
  loading is indicated by the tab icon only.
- **Secure lock.** Carried rule unchanged: the lock glyph shows when the pill value
  starts with `https://`. It reflects the shown address, not certificate state.
- **Routing.** A committed `http(s)` address navigates the **active web tab**; when
  the active tab is not a web tab it opens a new web tab. Suggestion activation takes
  the identical route. Non-`http(s)` schemes keep the carried opener routing.
  Non-address text keeps the carried in-bar failure row; no search engine is minted.
- **Ctrl+L / Cmd+L** focuses the pill and selects its content (carried). It applies
  to web tabs: from the chrome bar or strip it works as before; from **inside the
  page** it also works (see Keyboard and focus).

### Back / Forward / Reload

- Enablement is driven by the active web tab: **Back** enabled iff chrome's last
  push for the active tab reports history behind; **Forward** iff history ahead;
  **Reload** iff the active tab is a web tab that has a page (disabled for a tab with
  no page). All three are disabled when the active tab is not a web tab.
- Disabled is styled, never removed (carried `opacity: 0.4`, tooltip retained;
  layout never shifts).
- Each acts on the active web tab only. Reload keeps its label and icon while
  loading; there is no Stop.

### Failure surfaces (all copy in the table above)

| Situation | Surface | Next step on screen |
|-----------|---------|---------------------|
| Chrome refused or did not acknowledge an **open or navigate** issued from the pill or a suggestion | Carried in-bar failure row | Enter re-commits |
| Chrome refused or did not acknowledge the **open** issued by "+" | The new tab renders the lost-view state | Reload (enabled) / close tab |
| A **page failed to load** (network error, blocked, certificate) | Gecko's stock error page inside the overlay; tab icon stops spinning; pill keeps the attempted address; Back enabled if history exists | The error page's own "Try Again"; Back; type another address |
| A web tab's **overlay was lost** (chrome-side restart, unknown tab reported to a geometry/reload/back request) | Lost-view state in the tab body; pill keeps the last known URL | Reload / close tab |

No new dialog, toast, or status-bar flash is authored for any of these.

### Occlusion policy — body-portalled Theia layers

The overlay is composited above the whole Theia frame, so nothing drawn inside the
frame can appear above it. Contract:

- **Trigger.** Any of the following attached to `document.body`: the chrome bar's
  suggestion dropdown, the command palette / quick input, a Theia dialog overlay, a
  Theia menu.
- **Visible result.** The active web tab's overlay hides; its tab body shows the flat
  `--color-bg` placeholder surface (no text — the empty-state and lost-view lines
  never appear during occlusion). The Theia layer is fully visible and hittable.
- **Timing.** Hide **within one animation frame** of the layer attaching; restore
  **within one animation frame** of the layer detaching. No fade.
- **Scope.** Applies to every web tab whose placeholder is visible (normally only the
  active one). Hidden tabs are already hidden.
- **Accepted cost.** The page flashes to the dark surface while a suggestion
  dropdown is open (i.e. while typing in the pill). Recorded as an accepted
  simplification; the named upgrade if Chris rejects it is a chrome-side
  `clip-path` hole for the dropdown's rect (14.1-RESEARCH Pitfall 3).

### Mode switches and layout tracking

- A web tab **persists** across Coding, Browsing, Organising, and every second
  visit — never unmounted, closed, moved to another window, or detached (14-UI-SPEC
  invariant; the status-bar chip re-asserts it).
- The overlay **tracks the placeholder** on resize, tab switch, panel slide, hide,
  and close: geometry is republished on every layout change and the overlay rect is
  applied synchronously, so during the ≤200ms panel slide the page moves with the
  placeholder frame by frame. Any misalignment is bounded to **one frame**; at rest it
  is ≤1 CSS px.
- **Organising** activates the organising slot in the main area, so every web tab is
  a non-current main-area title: its placeholder is hidden and its overlay hides with
  it. Leaving Organising restores the previously active web tab and its overlay in
  the same frame the placeholder becomes visible.
- Hidden overlays stop painting and stop running foreground timers (chrome
  deactivates the hidden docshell) — a background web tab does not keep the page
  visibly active.
- No tab loading state on mode change (carried).

### Dependent windows (GUI-09) — deferred for web tabs

- A web tab **may not be moved to a dependent window this phase.** The overlay lives
  in the shell window and cannot follow a widget into a secondary `window.open`
  window.
- **Contracted behaviour when the user tries:** the move is **not offered** — the web
  tab is not extractable, so Theia's stock "move to secondary window" affordance does
  not appear for it in the tab context menu, and the shell never lists it as
  movable. There is no refusal message because there is no gesture to refuse.
- Existing dependent-window behaviour for other tab kinds is unchanged.
- Recorded as **deferred** (requires an overlay host per dependent window; out of
  scope per 14.1-RESEARCH Deferred Ideas).

### Setups and other openers (consequence, not a new surface)

- Because `http(s)` URIs now open through the web-tab open handler, **named setups
  restore** their saved web tabs as in-shell web tabs (previously stock windows), and
  Organising / Panorama see real rows for them. No new copy; 14-UI-SPEC restore
  copy stands.
- The palette command **"Open Browser Window"** (GUI-01) is unchanged and still opens
  the stock window.

### Known limitations recorded, not designed around (no copy, no UI)

- A link with `target=_blank` or `window.open` **inside a page** opens the stock
  browser window (GUI-01 path), not a new in-shell tab.
- Content `alert()` / `confirm()` / `prompt()` inside a page fall back to Gecko's
  window-modal prompt; right-click inside a page shows no context menu; find-in-page
  and zoom shortcuts inside the page are not provided.
- Two web tabs on the **same URL** share one store row (same ceiling as the stock
  `webview:` rule).

### Keyboard and focus

- **Focus order inside the Theia frame (Tab key):** chrome-bar controls in DOM
  order (Back, Forward, Reload, address input, New Tab, mode segments) → Theia tab
  strip (stock) → the active tab's content. For a web tab the content stop is the
  **placeholder node** (`tabindex="0"`), which shows the inset accent outline.
- **Entering the page by keyboard:** with the placeholder focused, **Enter** or
  **Space** moves focus into the page (chrome focuses the overlay). Clicking anywhere
  on the page also focuses it (the overlay is on top, so pointer focus is natural).
- **Leaving the page by keyboard:** **Ctrl+L / Cmd+L** while the page is focused
  moves focus to the address pill and selects its content — the same binding and
  result as inside Theia. This requires a shell-reserved key because Theia does not
  see keystrokes while the page has focus; the mechanism is the planner's (the
  keyset precedent exists in the shell). Clicking any Theia surface also leaves the
  page. No F6 binding is introduced (no precedent in the tree).
- **Other Theia keybindings while the page has focus** are not delivered this phase
  (recorded limitation, 14.1-RESEARCH Pitfall 8). Only Ctrl+L / Cmd+L is guaranteed
  to leave the page.
- **New Tab keybinding:** none. `chrome-bar-keybindings.ts` binds only
  `ctrlcmd+l`; no Ctrl+T precedent exists and none is invented. "+" is reachable by
  Tab-key focus + Enter on the New Tab button, and via the palette command "New Tab".
- **Close keybinding:** stock `core.close` (Alt+W in the browser target).

### Accessibility

- The **placeholder node** carries `tabindex="0"` and `aria-label` equal to the tab's
  label (page title → URL → "New Tab"), updated on every title/URL change, so a
  screen reader names the page the focused region stands for.
- The **tab title** is announced through Theia's stock tab-strip semantics
  (unchanged); the label text is the same string as the placeholder `aria-label`.
- The **loading icon** is decorative (`aria-hidden`); loading is not announced
  beyond the label change. The empty-state and lost-view lines are live text in the
  placeholder and are read when the placeholder is focused.
- Nav buttons keep their carried `aria-label`s; the disabled state is the native
  `disabled` attribute (announced by assistive tech).
- Focus indicators: every net-new focusable (placeholder) and every carried control
  shows the contracted accent outline (WCAG 2.4.7 / 2.4.11).
- Colour is never the sole carrier of any state (see Contrast).

## Assumptions (auto mode)

Each row is a decision this spec made because no CONTEXT.md and no user were
available. Each picks the option most consistent with the locked sources and the
Theia stock idiom. Chris or the planner may overturn any row; overturning one does
not invalidate the others.

| # | Decision | Chosen | Why this option | Alternative not taken |
|---|----------|--------|-----------------|-----------------------|
| A1 | Bare "+" initial page | Empty page (`about:blank` chrome-side); overlay **not shown** while the tab has no page; placeholder shows the empty-state line; pill focused | Research rejects `about:newtab` (needs `browser.xhtml` machinery); a blank remote document paints white, which would flash against the dark theme, so the dark placeholder is shown instead | Show the blank document; load a bundled start page (new surface, out of scope) |
| A2 | Empty-state copy | One muted line "Type an address above to get started." | The pill is the single affordance and is already focused; one line orients without inventing a start page | No text at all (an unlabeled dark rectangle reads as broken) |
