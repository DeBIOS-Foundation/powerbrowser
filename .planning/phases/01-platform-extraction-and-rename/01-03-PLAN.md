<objective>
Hand-write every branding value the rename script was forbidden to touch, create the original
placeholder mark, and build the two cheap static gates that make a typo cost seconds instead of a
forty-minute Gecko build.

Purpose: Pitfall 1 is the phase's central hazard — the TitleCase form is simultaneously a display
name and an identifier prefix, and a single global replace produces a build that succeeds, a window
titled with the wrong string, and a verifier that agrees because the same pass rewrote its
expectation. The defence is that these surfaces are hand-written from the inventory's declared
targets and cross-checked against a third source before the build runs.

Output: correct display literals on all six surfaces, working `.desktop` entries, an original square
mark rasterized to ten PNGs, `scripts/verify-branding-preflight.mjs`, and the consolidated
`scripts/verify-platform.sh`.
</objective>

  <action>
**The preflight (`scripts/verify-branding-preflight.mjs`).** A Node ESM CLI that runs in seconds with
no build. It reads the `brand-display` rows from `inventory/brand-tokens.json` and asserts, for every
one, that the named file carries exactly the row's declared `target` at the declared site. It then
asserts that `verify-branding-identity.mjs`'s VARIANTS descriptor agrees with those same targets for
every surface it covers, and that the machine-side vendor value in the mozconfig and the display-side
vendor value in the branding files are the two distinct expected values the identity verifier will
compare against.

The expected-value source is the inventory, deliberately. The failure this exists to catch is the
tautology: a verifier whose expectation was rewritten by the same pass that rewrote the value it
checks will agree with a wrong answer, the build will succeed, and the window title will be wrong.
The inventory's `brand-display` targets were authored before any hand-writing, from the recorded
identity decisions, so it is a third source that neither the rename script nor the hand-write task
produced. Carry that reasoning in the file's header, the way every other guard in this tree carries
its rationale.

Include a `--self-test` in the established idiom: plant a fixture in a temp directory whose display
literal disagrees with its inventory row, assert the preflight rejects it, and assert the rejection
message names the offending file and both values. Fail with a distinct message when the set of
`brand-display` rows is empty — an empty check set is not a clean result.

**The consolidated driver (`scripts/verify-platform.sh`, D-21).** Port every assertion from
`verify-phase-02.sh` through `verify-phase-05.sh` into one driver and delete the four per-phase
shells. Keep the driver skeleton verbatim: the deliberate `set -uo pipefail` with no `-e` so a failing
check does not abort the rest, the `REPO_ROOT` derivation used by every other script in the tree, the
