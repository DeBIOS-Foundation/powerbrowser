# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note.** This phase has no web app. Its UI surfaces are (a) a Gecko privileged-chrome
window under a `default-src chrome:` CSP, (b) Firefox branding-slot files, (c) React widgets
running inside Eclipse Theia's own theme system, and (d) two net-new GUI features (GUI-01,
GUI-02) that are explicitly built out of *stock* upstream UI. The governing constraint is
Phase 2's acceptance test — the generator must reproduce Phase 1's hand-written files
byte-for-byte — so **every invented visual value here becomes a hardcoded brand literal that
Phase 3 must emit and Phase 6's VER-01 scan must police.** The contract below therefore
inherits from Gecko and Theia wherever possible and declares Power-Browser-specific values
only where the tree already has one.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — shadcn deliberately not initialized (see rationale) |
| Preset | not applicable |
| Component library | Gecko chrome: none (raw XHTML). Theia side: `@theia/core` widgets + `@theia/mini-browser@1.74.1` (GUI-02 only) |
| Icon library | none added. Gecko branding PNG set (16/32/48/64/128) + one inline SVG mark data URI. Theia supplies codicons for its own chrome. |
| Font | Generic families only: `sans-serif` (UI) and `monospace` (diagnostics log). Theia side delegates to `--theia-ui-font-family`. |

**Why shadcn is not initialized (checker: this is a deliberate `Tool: none`, not an omission):**

1. The shell document declares `<meta http-equiv="Content-Security-Policy" content="default-src chrome:">`. No `unsafe-inline`, no external origins. A Tailwind/shadcn build emits either an inline `<style>` or a non-`chrome:` stylesheet — both are **silently dropped** by Gecko, yielding a 0×0 viewport with nothing logged. `powerbrowser/shell/powerbrowser.css` header comment documents this exact failure mode from a prior regression.
2. The Theia-side React widgets are not a React app. They render inside Theia's shell and inherit its CSS-variable theme (`--theia-*`). Bolting on a second token system forks theming and breaks the Phase 4 promise that a rebrand triggers no TypeScript recompile.
3. `components.json` is absent and must stay absent. Nothing in this repo is a Vite/Next app.

**Sources:** `powerbrowser/shell/powerbrowser.css:1-28` (CSP rationale), `theia/package.json`
(49 pinned `@theia/*` at 1.74.1), 01-RESEARCH.md *Standard Stack*.

## Spacing Scale

Declared values (all multiples of 4). The shell expresses these in `em` at a 16px root so
OS text scaling is respected in privileged chrome; px column is the equivalence at default root.

| Token | Value | Shell `em` | Usage |
|-------|-------|-----------|-------|
| xs | 4px | `0.25em` | Diagnostics field row gap |
| sm | 8px | `0.5em` | Control vertical padding |
| md | 16px | `1em` | Control-group gap, diagnostics layer gap, log well padding |
| lg | 24px | `1.5em` | Error deck gap (message ↔ controls) |
| xl | 32px | `2em` | Error / diagnostics layer inset padding |
| 2xl | 48px | — | Not used in Phase 1 |
| 3xl | 64px | — | Not used in Phase 1 |

Radius: `4px` on all shell controls and the diagnostics log well. Border: `1px`.
Control horizontal padding is `1.25em` (20px) — a multiple of 4, kept as-is.

**Exceptions (declared, not accidental):**

| Exception | Value | Why it stands |
|-----------|-------|---------------|
| Gecko icon raster sizes | 16 / 32 / 48 / 64 / 128 px | Fixed by Gecko's branding slot and the Linux icon spec. Not ours to choose. |
| `branding/{dev,release}/content/aboutDialog.css` | `margin-inline: 30px`, `padding: 15px 10px`, `background-size: auto 44px` | Inherited from Firefox's own about-dialog geometry; the file is a branding-slot override, not our layout. **Migrates verbatim (debrand only).** Restyling it is Phase 3 emitter scope, not rename scope. |
| Sourcerer mark render sizes `64×56` / `48×42` | non-square | Artifacts of the Sourcerer mark's `viewBox="0 0 99 85.9"`. **Eliminated in Phase 1** — see Brand Asset Contract; the square placeholder makes both `64×64` / `48×48`. |

## Typography

Power Browser owns only the shell scale. Theia-side type is delegated — do **not** redeclare it.

### Gecko shell (owned)

| Role | Size | `em` | Weight | Line Height | Applies to |
|------|------|------|--------|-------------|------------|
| Display | 24px | `1.5em` | 400 | 1.2 | `#powerbrowser-loading` wordmark |
| Heading | 20px | `1.25em` | 400 | 1.5 | `#powerbrowser-error-message` |
| Body | 16px | `1em` | 400 | 1.5 | Buttons, diagnostics field rows |
| Mono | 13.6px | `0.85em` | 400 | 1.5 | `#powerbrowser-diagnostics-log` (`monospace`) |

Exactly 4 sizes, exactly 2 weights permitted (400 regular, 600 semibold). 600 is currently
unused in the shell and must stay unused unless a heading needs it — the deck's hierarchy is
carried by size and stacking order, not by weight.

`0.85em` (13.6px) is an inherited value. It is **not** normalized to `0.875em` in this phase:
a rename diff that also reshapes is unreviewable (01-RESEARCH.md *Recommended Project
Structure*). Normalize in Phase 3 if the emitter touches the file.

### Theia side (delegated — do not declare)

Welcome widget and about dialog use Theia's `gs-container` / `ad-container` classes and its
`h1` / `h3` / `p` defaults, sized from `--theia-ui-font-size` and `--theia-ui-font-family`.
No font-size, font-family, or font-weight literal may be added to
`@powerbrowser/branding` or `@powerbrowser/tab-uris`. A downstream restyles through
GUI-03's `customize.css` layer; a hardcoded size defeats that.

## Color

Read off the existing shell, which is a genuine 60/30/10 split by painted area.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1a1a1a` | `html`/`body` and all three deck layer backgrounds (loading, error, diagnostics) |
| Secondary (30%) | `#333` (control surface), `#444` (control `:hover`), `#111` (diagnostics log well), `#555` (control border), `#333` (well border) | Buttons, the log well, borders |
| Accent (10%) | `#e8e8e8` | See reserved-for list below |
| Destructive | **none declared** | No destructive action exists in this phase |

**Accent reserved for — exhaustive list:**

1. Foreground ink on all three deck layers (loading wordmark, error message, diagnostics field rows and log).
2. Control label text on the three shell buttons.
3. The `:focus-visible` outline on those three buttons — **net-new, see below.**

Nothing else. `#e8e8e8` must never be used as a fill or a surface.

### No brand hue in Phase 1 — deliberate

The tree today contains **zero invented brand colours**, and the reason is recorded in
`theia/extensions/branding/src/browser/*-mark.ts`: *"`#1a1a1a` is a neutral dark, not a chosen
brand colour."* Phase 1 keeps that property. A Power Browser brand hue introduced now would be
a hardcoded literal that Phase 3's emitter must generate, Phase 6's VER-01 static scan must
police, and Phase 7's fixtures must vary. It belongs with the real logo (D-11 defers it) or
with a `[colors]` block in `configuration.toml`. **The executor must not invent one.**

### Residual Mozilla brand value — must be replaced

`branding/{dev,release}/content/aboutDialog.css:7,13`

```css
background-color: #130829;                      /* Mozilla's dark purple */
background-color: hsla(235, 43%, 10%, 0.5);     /* the same hue, translucent */
```

These are **Mozilla brand values**, not neutrals, sitting inside Power Browser's branding
directory. They are invisible to the D-16 residual scan because the scan matches brand
*tokens* (`sourcerer`, `Deocracy`), not hexes. Replace with the shell's neutral pair so the
about dialog matches the shell and no upstream brand hue ships under the Power Browser mark:

```css
background-color: #1a1a1a;
background-color: rgba(17, 17, 17, 0.5);        /* #111 at 50%, the diagnostics-well neutral */
```

Add both hexes to the inventory's `coincidental`/allowlist bucket so the Phase 6 scan can be
taught about them rather than rediscovering them.

### Contrast

`#e8e8e8` on `#1a1a1a` ≈ 14.6:1 — passes WCAG AAA at all four type sizes. `#e8e8e8` on `#333`
(button) ≈ 10.4:1 — passes AAA. No pairing in this contract needs remediation; do not
introduce a mid-grey text colour that would.

### Net-new: focus-visible outline

The three shell buttons (`retry`, `diagnostics`, `diagnostics-close`) currently define **only**
`:hover`. A keyboard user gets no visible focus indicator — and the error deck is exactly the
state a user reaches when the pointer-driven happy path has already failed. Required:

```css
#powerbrowser-error-retry:focus-visible,
#powerbrowser-error-diagnostics:focus-visible,
#powerbrowser-diagnostics-close:focus-visible {
  outline: 2px solid #e8e8e8;
  outline-offset: 2px;
}
```

Uses the declared accent and the declared 4px scale. WCAG 2.4.7 / 2.4.11.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Retry"** — shell error deck; retries backend startup. Kept verbatim: the full-screen message directly above it names what failed, so a verb-only label is unambiguous here. |
| Secondary CTA | **"Details"** — opens the diagnostics layer. Kept verbatim. |
| Dismiss CTA | **"Close"** — closes the diagnostics layer. Kept verbatim. |
| GUI-02 escape CTA | **"Open in browser window"** — net-new, always visible on every web tab. See Interaction Contract. |
| Empty state heading | Not applicable to the shell (the deck is never empty — a layer is either painted or hidden). GUI-02 tab with no URL uses `@theia/mini-browser`'s stock empty state; **do not author replacement copy.** |
| Empty state body | — as above — |
| Error state | Two-part, plain language: **what failed** + **what to do next**. Internal identifiers are forbidden in this string; they belong in the diagnostics layer, which exists for exactly that. See rewrite table below. |
| Destructive confirmation | **None in this phase.** Retry / Details / Close are all non-destructive. If the GUI-01 spike surfaces a quit-on-last-window path, that is an interaction defect to fix (see Interaction Contract), not a confirmation dialog to add. |

### Error-copy rewrite — the one Dimension-1 gap in the migrated tree

`TheiaService.sys.mjs` writes internal sentinel names and pref keys straight into
`#powerbrowser-error-message`, which is user-facing full-screen text. A pure rename carries the
leak forward with a new prefix. Required rewrites:

| Current (`TheiaService.sys.mjs`) | Required user-facing copy |
|---|---|
| `sourcerer.sidecar.backendMain is unset -- cannot locate the Theia backend entry file.` | **"Power Browser can't find its interface files. This build looks incomplete — reinstall, or open Details for the missing path."** |
| `sourcerer.sidecar.backendMain (${path}) does not exist -- ...` | same string as above (the path goes to Details) |
| `Could not resolve a Node executable -- set sourcerer.sidecar.nodePath or add node to PATH.` | **"Power Browser needs Node.js and couldn't find it. Install Node.js 22 or later and open Power Browser again, or open Details for where it looked."** (01-13: reworded. Reachable only from `_resolveSidecar`, which is always classified unrecoverable, so the screen it paints has no Retry control on it.) |
| `Failed to spawn the backend: ${err.message}` | **"Power Browser couldn't start its interface, and retrying won't change the result. Close Power Browser and open it again, or open Details to see the error."** (01-13: `USER_MESSAGE.couldNotStartUnrecoverable`, minted for the two `recoverable: false` sites in `_spawnAndGate` — the D-113 spawn-throw and the D-112 pinned-port conflict.) |
| `Failed to hand the backend its token over stdin: ${err.message}` | **"Power Browser couldn't start its interface. Choose Retry, or open Details to see the error."** (`USER_MESSAGE.couldNotStart` — this site is classified recoverable, so Retry is on the screen and naming it is correct.) |
| `Backend output stream ended before announcing readiness: ${err.message}` | same string as the stdin row above, except D-112's pinned-port conflict, which is classified unrecoverable and takes `couldNotStartUnrecoverable` |
| `Backend did not announce SOURCERER_BACKEND_READY within ${ms}ms.` | **"Power Browser's interface didn't finish starting. Choose Retry, or open Details if this keeps happening."** |
| `Health probe on port ${port} never returned 200 within ${ms}ms.` | same string as above |
| `Shutting down.` | keep verbatim — not an error surface |

Rules the executor applies: every user-facing string names the product as **"Power Browser"**,
states the problem in plain language, and ends with a next step that is a real affordance on
screen (Retry or Details). Every dropped identifier — pref key, sentinel, port, timeout,
`err.message` — is added to the diagnostics field rows so nothing is lost.

**The rule 01-13's gap taught, added to the list above:** the stated next step and the set of
controls rendered for that classification are **one fact and change together**. A failure the
supervisor classifies unrecoverable is not offered a Retry control, so no message reachable from an
unrecoverable call site may name Retry as the next step — for that class the on-screen affordance is
Details, and Details alone. This is why `couldNotStart` split into two entries: the distinction the
new key carries is not a distinction of cause (which the user cannot act on and which 01-10 rightly
declined to mint a key for) but a distinction of *which controls exist on the screen the sentence is
printed on*, which is the one thing the sentence has to be right about.

⚠ **Planner judgment call.** This rewrite is 9 strings inside files the rename already edits,
but it is *behaviour* change inside a mechanical-rename phase. If the planner scopes it out,
the phase still satisfies MIG-01..04 — but Dimension 1 will not pass, and the leak becomes
Phase 6's problem. Recommendation: keep it, as its own commit after the rename stages land,
so the rename diff stays purely mechanical and bisectable (D-06). Any smoke/verify assertion
matching an old literal must be updated in that same commit.

## Brand Asset Contract (D-11 placeholder mark)

| Property | Value |
|----------|-------|
| Source | One SVG, hand-authored, original geometry |
| `viewBox` | **Square** — `0 0 128 128` |
| Fill | Two-value pair inside the SVG's own `<defs><style>`: `#1a1a1a` default, `#fff` under `@media (prefers-color-scheme: dark)` |
| Rasters | `default{16,32,48,64,128}.png` in `branding/{dev,release}/`, rendered at target density from the one source |
| Theia render size | `64×64` (welcome widget), `48×48` (about dialog) |
| Delivery | Inline `data:image/svg+xml,${encodeURIComponent(...)}` export from `@powerbrowser/branding`, same pattern as today |

**Square is a requirement, not a preference.** Sourcerer's mark is `99×85.9`, which is the sole
reason the widgets carry `64×56` / `48×42` magic numbers. Gecko's icon slots are square;
Phase 3's GEN-02 rasterizes five square sizes from one source; Phase 7's adversarial fixtures
list *non-square logo* as a case that must fail loudly. A square placeholder deletes all three
problems and the two magic numbers.

**The `prefers-color-scheme` pair is load-bearing** — the mark ships as a favicon on the tab
strip, which follows the OS theme independently of the shell's fixed dark background. A
single-fill mark disappears on one of the two. Carry the pattern forward verbatim (D-36).

**Non-derivative.** Sourcerer's `logo/` stays downstream (D-03). The placeholder must not be a
recolour, crop, or rearrangement of the crossed-lens-and-dots mark. Simple geometry,
unmistakably a placeholder, and no wordmark inside the SVG (the wordmark is text in the
loading layer, so it renames without touching the asset).

## Interaction Contract (GUI-01 / GUI-02, net-new)

Both features are built out of *stock* upstream UI. **No custom browser chrome is authored in
this phase** — no tab strip, no toolbar, no address bar. That is Milestone 2.

### GUI-01 — Theia ⇄ browser window

| Contract | Requirement |
|---|---|
| Browser presentation | A **stock** `chrome://browser/content/browser.xhtml` window. Zero Power Browser styling, zero overrides. The whole point of restoring `BROWSER_CHROME_URL` to its upstream value (01-RESEARCH.md *Finding 1*) is that address bar, tabs, and modal dialogs behave natively. |
| Entry affordance | One Theia command, palette-reachable, labelled **"Open Browser Window"**. |
| Return affordance | Closing the browser window returns focus to the shell window. No second command. |
| ⚠ Last-window hazard | Closing the browser window **must never quit the application.** Gecko quits on last-window-close; if window ordering ever leaves the browser window last, "and back" silently becomes "and gone", losing Theia state. 01-RESEARCH.md flags this as unverified. Must be exercised in the D-20 spike alongside the `BROWSER_CHROME_URL` call-site check. |
| Startup flicker | The early `navigator:blank` window is closed rather than reused, producing a brief flicker upstream's own comment calls acceptable. **Accepted, documented, not fixed in Phase 1.** |

### GUI-02 — web pages as Theia tabs

| Contract | Requirement |
|---|---|
| Widget | `@theia/mini-browser@1.74.1` stock widget, opened through an `http:`/`https:` `OpenHandler` in `@powerbrowser/tab-uris`. Stock styling; no custom widget chrome. |
| Addressability | The URL is the widget's resource URI, so the tab round-trips through the existing `TabUriRegistry` unchanged. |
| Loading / error states | `@theia/mini-browser` stock. Do not author replacements. |
| ⚠ Frame-refusal escape | Every web tab carries an always-visible **"Open in browser window"** action that hands the current URL to GUI-01. |

**Why an always-on affordance rather than a detected error state.** A site sending
`X-Frame-Options: DENY` or a restrictive `frame-ancestors` renders as a blank iframe and fires
no reliable error event — detection is a timeout heuristic that will misfire on slow pages.
A persistent escape hatch is smaller code, never wrong, and gives a user staring at a blank
tab a working next step with no detection at all. It is also the exact complementarity the
research identified: sites that refuse framing are what GUI-01's real browser window is for.

Ship the fifth `CARVE_OUTS` entry in `existing-scheme-coverage.ts` plus the
`docs/URI-SCHEMES.md` section so the boundary is asserted as documented behaviour, not filed
as a defect later.
