<objective>
**As a** Power Browser user whose interface failed to start, **I want to** press Retry, see it fail,
and still have a message and a working Retry in front of me, **so that** a transient failure costs
me one more click instead of the whole session.

Close 01-VERIFICATION.md's failed truth 2c (CR-01). `powerbrowser.js`'s `powerbrowserRetry` hides
the error layer with a direct `errorElement.style.display = "none"` and then calls
`TheiaService.retry()`, which is `await this._restart()` and never clears `_errorShown`. So on the
FIRST Retry that does not succeed, the DOM is already blank and `_showError`'s `if (this._errorShown)
{ return; }` guard swallows every subsequent repaint for the life of the session: no message, no
Retry, no Details, forever. `_hideError()` never running also means the stale recovery probe from the
original failure is still live with zero on-screen feedback.

This shipped green through 01-08, 01-09 and 01-10's full verification runs because no registered
check ever observes a SECOND error sentinel — `shell03-budget-exhausted-error` asserts there is
exactly ONE, which is correct for the launch it drives and blind to this one.

Purpose: MIG-04's "boots, and works as an actual web browser" clause. Retry is the single most
likely user action in the error state and it currently disarms the only affordance on screen.
Output: one supervisor-routed hide, one entry point that stops writing the DOM behind the
supervisor's back, one new registered analyzer that drives two consecutive failing retries against
the shipped source, and one source-derived set-equality rule that catches the next function to blank
the error layer.

caller that owes a repaint. Note in the same comment that `_hideError()` early-returns when
`_errorShown` is false, so the health loop's and `start()`'s own `_restart()` calls are unaffected.

`powerbrowserRetry`, leaving the guarded `TheiaService.retry()` call as the function's only

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input (Retry click) → privileged chrome JS | The only user-reachable control in the failure state. A click crosses from the rendered chrome document into the supervisor's restart path. |
| supervisor state (`_errorShown`) ↔ rendered DOM | Two representations of one fact, in two files, previously mutated independently. Divergence here is the defect. |
| shipped source → `verify-shell-error-contract.mjs` harness | The analyzer evaluates privileged chrome source in a Node process. Nothing crosses back: the harness writes only to `mkdtemp` scratch and reads only the two source files. |

## STRIDE Threat Register (ASVS L1, block on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11-01 | Denial of Service | `TheiaService.retry()` / the chrome error layer | medium | mitigate | A failed Retry permanently disables the only affordance the failure state offers — a self-inflicted availability failure of the recovery path, reachable by the single most likely user action. Task 1 routes the hide through `_hideError()` so `_errorShown` is cleared and the next `_showError` repaints; the registered analyzer requires the second and third sentinels across two consecutive failing retries. |
| T-01-11-02 | Denial of Service | `_stopRecoveryProbe()` reachability | medium | mitigate | Because `_hideError()` never ran on a failed Retry, `_stopRecoveryProbe()` never ran either, leaving the original failure's probe driving restarts invisibly for the session. | T-01-11-03 | Information Disclosure | the `POWERBROWSER_SHELL_ERROR` sentinel payload on repaint | low | mitigate | A second, repainted sentinel is a second chance to leak the per-launch token or a raw exception string onto a channel the diagnostics layer renders.
