# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is a no-regression contract.** Phase 19 is a dependency upgrade: Node 24, React 19.2.8,
and every `@theia/*` package except `@theia/monaco-editor-core` moved to 1.76.0. It adds no
visual design. Every surface PowerBrowser authored must look and behave exactly as it did at
Theia 1.74.1 / React 18. The only intended visible changes are the ones listed in
"Intended visible changes" below. Anything else that changes on screen is a defect.

Sources: 19-CONTEXT.md (locked decisions), REQUIREMENTS.md RM-02 and UPD-07..UPD-10,
ROADMAP.md Phase 19 success criteria 3 and 4, `.planning/research/STACK.md` sections B and
"New transitive extensions", and the copy contract in
`.planning/milestones/v1.0-phases/01-platform-extraction-and-rename/01-UI-SPEC.md`.

---

## Out of Scope

- New visual design of any kind: no new component, layout, icon, colour, spacing value, font
  size, weight, radius, shadow or motion value.
- Any edit to an authored stylesheet (`theia/extensions/*/src/browser/*.css`). The phase's
  diff touches no `.css` file.
- Restyling, re-theming or customising any `@theia/ai-*` surface. RM-02 keeps them stock;
  customising them is a later milestone.
- Removing `@theia/ai-ide` to drop `@theia/getting-started` from the closure (STACK.md: a DSH
  product decision, not a version-update fix).
- Fixing pre-existing spacing exceptions in shipped CSS (6px, 10px, 12px values in
  `chrome-bar.css`). They are recorded below as frozen, not corrected.

## Typography

Body line height is inherited unchanged from Theia 1.74.1; a visible change to it at 1.76.0 is a defect under V4, not an intended change.

Frozen. The phase declares no type value. Shipped values, for reference:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label (chrome bar, tab strip) | 12px | 400 | Theia default |
| Body (chrome bar, address field) | 14px | 400 | Theia default |
| Heading (welcome, about) | Theia `gs-container` / `ad-container` defaults | 600 | Theia default |

All other text is Theia-delegated and changes only if upstream 1.76.0 changed it.

## Color

Frozen. Shipped values (sketch theme `default.css`, present verbatim in `chrome-bar.css` and
`modes.css`):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #1c1b22 | Shell background |
| Secondary (30%) | #2b2a33 / #35343f | Chrome bar, tab strip, raised surfaces |
| Accent (10%) | #00a6f5 | Reserved list below |
| Destructive | #ff848b | Error and close-danger states only |

Accent reserved for (as shipped in `chrome-bar.css` and `modes.css`): `:focus-visible` rings
on chrome-bar buttons, segments, tabs, tab close, Panorama rows and titles; the address pill's
`:focus-within` ring; the active mode segment (`.pb-chrome-bar-segment.is-active`); the active
Panorama view toggle (`.pb-org-toggle-segment.is-active`); the tab-strip drop target. No
element gains or loses the accent in this phase.

Default theme stays `dark` (`frontend.config.defaultTheme`). Dependent (secondary) windows
must render in the same dark theme as the core window (STACK.md open question; a light-themed
dependent window is a regression).

## No-Regression Contract

Each item is an observable check a live sidecar run makes. Live runs use `PB_VERIFY_PORT`
(default 3939), never port 3000, on a sidecar rebuilt after the last change. Commits 2
(React 19) and 3 (Theia 1.76.0) each run items N1–N4; item N3 needs 1.76.0 and runs after
commit 3.

### N1 — First-boot surface (UPD-10, ROADMAP criterion 3)

Run on a **fresh** config dir and on a **carried-over** one (a config dir last written by the
1.74.1 sidecar, with a persisted layout).

- Exactly one main-area tab opens at startup: the PowerBrowser welcome, widget id `welcome`.
- No widget with id `getting.started.widget` exists in the shell. Check by id, not by label:
  both widgets are titled "Welcome".
- No `theia-ide.org` link is anywhere in the rendered DOM.
- No AI Configuration tab, no AI chat tab, and no "AI First" layout opens at startup.
- `workbench.startupEditor` resolves to `none` from the app's default preferences, in both
  config dirs. On the carried-over dir this holds unless the user had set the preference
  themselves.

### N2 — PowerBrowser-authored surfaces render under React 19

For each surface below: it paints non-empty content, shows no React error overlay, and logs
no render error to the console.

| Surface | Source | Observable check |
|---------|--------|------------------|
| Welcome tab | `powerbrowser-welcome-widget.tsx` | Mark at 64×64, product name, welcome text, repo link `https://powerbrowser.org` |
| About dialog | `powerbrowser-about-dialog.tsx` | Mark at 48×48, name, Version line, one repo link, the three legal notices; no `@theia/*` package list |
| Chrome bar | `chrome-bar-widget.tsx` | Address field, navigation controls, mode toggle all present |
| Chrome-bar dropdown | `chrome-bar-widget.tsx` portal (`createPortal`) | Opens anchored under its trigger (`getBoundingClientRect` position matches the trigger's bottom edge), not at the page origin |
| Tab strip | `tab-strip-widget.tsx` | One tab per open web tab; keyboard focus shows the accent ring; relocates per mode |
| Modes | `modes` extension | Each shipped mode applies; the tab strip moves to that mode's position |
| Panorama | `organising-widget.ts` | Cards render for open tabs; tree toggle switches views |
| Dependent windows | `dependent-windows.ts` | A moved tab opens in a secondary window with live content, in the dark theme; closing it returns focus to the core window |
| Web tab | `tab-uris` `web-tab.ts` | A `https://` URL loads in a Theia tab |

### N3 — Settings shows PowerBrowser's telemetry copy (locked decision)

- Settings → `telemetry.telemetryLevel` shows the description **"How much usage and error
  telemetry PowerBrowser sends to the configured endpoint."** and the four PowerBrowser enum
  descriptions from `telemetry-preferences.ts`. It does not show `@theia/telemetry`'s text.
- The default stays `off`; values stay `off`, `crash`, `error`, `all`.
- The PowerBrowser registration wins deterministically (not by module load order), and a live
  check asserts it on both config dirs. The mechanism is the planner's; the SUMMARY records it.

### N4 — Render errors and token gate

- `telemetry-error-capture` (window `error` and `unhandledrejection` listeners) captures zero
  render errors during the N1–N2 walk.
- One deliberately forced render error in a PowerBrowser widget reaches telemetry capture
  under React 19 (`ng067-frontend-errors-reach-telemetry`). This proves the listener still
  sees React 19's uncaught errors and that a zero count in the first item is real.
- `view:` URIs open their views (`view:welcome`, `view:ai-configuration` at minimum).
- `side02-token-negative` and `side02-token-positive` pass live.

## Copywriting Contract

The phase adds no user-facing string. If the planner finds one is needed, it follows the
Phase 1 rule: name the product "PowerBrowser", state the problem in plain language, end with a
next step that is a real affordance on that screen, and carry no internal identifier (no pref
key, port, timeout, package name, widget id or raw exception message). Identifiers go to the
diagnostics layer. `shell-error-copy-no-internals` enforces this.

| Element | Copy |
|---------|------|
| Primary CTA | None new. Existing labels ("Retry", "Details", "Close", "Open in browser window", "Toggle Welcome") stay verbatim. |
| Empty state heading | None new. A URL-less web tab keeps `@theia/mini-browser`'s stock empty state. |
| Empty state body | None new. |
| Error state | None new. Existing shell error copy (01-UI-SPEC rewrite table) stays verbatim. A new error string, if one is added, is: "PowerBrowser couldn't <plain-language problem>. <Retry or Details, matching the controls on that screen>." |
| Destructive confirmation | None. The phase adds no destructive action. |
| Settings: `telemetry.telemetryLevel` description | "How much usage and error telemetry PowerBrowser sends to the configured endpoint." (existing, must be the displayed one; see N3) |

Upstream copy on upstream surfaces (AI views, the Startup Editor preference, the perspective
picker) is stock and is not rewritten.
