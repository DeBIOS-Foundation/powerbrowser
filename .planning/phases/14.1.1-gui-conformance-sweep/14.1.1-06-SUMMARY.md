# Phase 14.1.1 Plan 06: Thumbnail Attribution Summary

**A third served page whose response never ends — so it paints but never reaches network STOP — makes the stored PNG attributable to `webTabGeometry`'s last-view hide alone, and a plant that removes that hide turns the thumbnail assertions red.**

## Accomplishments

- **Which page shape shipped: the HANGING page — the plan's primary bet, not the fallback.** `/c` is served with `res.writeHead` + `res.write` and never `res.end`, so the document commits and paints while the load never completes. The capture bet won on the very first clean run: `baseline before the hide: absent true (length 0); after the hide: hasThumbnail true, prefixOk true, length 838`. `PageThumbs.captureToCanvas` yields a real PNG for a painted-but-unfinished document, so the fallback branch (a terminated, time-varying page asserting CHANGE rather than presence) was never entered and no discriminating run was needed.
- **The evidence is now attributable.** The phase navigates the overlay to `servedC` through the widget's own `navigate()` (the same `webTabNavigate` the pill commit issues), waits for the store row chrome's `onLocationChange` writes, outwaits twice the derived `TAB_THUMBNAIL_SETTLE_MS`, reads a baseline that must be ABSENT, and only then hides. Deleting the chrome-side hide arm at `PowerBrowserAPI.sys.mjs:2358-2365` now empties that row: the network-STOP arm at `:2263` cannot fire for a page that never reaches STOP, and the mode walk ran several phases before `servedC` existed.
- **The plant now removes a cause, not a reader.** `thumb-not-scheduled` (which replaced `P.thumbnailOf` with a stub — its own comment admitted it stripped the read) is gone. `hide-not-published` replaces `P.hideOverlay` with a no-op and goes red naming `thumbnail`, with the residual stated plainly in the plant comment: no page-realm plant can edit chrome source, so this removes the frontend half of one causal chain whose chrome half produces the identical three reds.
- **Plant count unchanged: 11 in, 11 out.** One removed, one added. `--self-test: PASS -- the clean control is green and all 11 planted faults went red`.
- **A second shell constant is derived, never typed.** `derived.thumbnailSettleMs` reads `TAB_THUMBNAIL_SETTLE_MS` from `PowerBrowserAPI.sys.mjs` in exactly the regex-and-Number shape `thumbnailMaxChars` already used, and a zero derivation is a named FAIL.
- **`powerbrowser/shell/PowerBrowserAPI.sys.mjs` is untouched.** `git status` over `powerbrowser/` lists only the concurrent session's `jar.mn`; `git -C upstream diff` is empty.

## Decisions Made

- **The hanging page over the time-varying fallback.** The plan named two shapes and told me how to discriminate. The primary shape worked on the first run, so the discrimination step (drop the `hang` marker, re-run, see whether a terminated page captures where a hanging one does not) was never needed and was not run. The plan required the summary to name the shipped shape and, if the fallback shipped, the discriminating run: the fallback did not ship, so there is no such run to report.
- **`server.closeAllConnections()` before `server.close()`.** The hanging response holds its socket for the whole run; `server.close()` alone waits for it forever and every session would hang at teardown.
- **4 KB of padding in the hanging body.** The HTML parser flushes on byte count as well as on end-of-stream. A short never-ended document risks sitting unparsed in a buffer and never painting, which would have looked exactly like a lost capture bet.
- **The seam moved from task 2 into task 1.** See deviations.

**3. [Rule 1 - Bug] The rewritten phase overran the 20s BiDi evaluate budget**
