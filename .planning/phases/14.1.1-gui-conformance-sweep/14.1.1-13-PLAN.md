<objective>
Close the build-order gate's specifier blind spot, then correct the two records that overstate
or misdescribe it.

Purpose: `verify-theia-build-order.mjs:131` matches `/\bfrom\s*['"]@powerbrowser\/.../g`, which
finds zero matches against `import '@powerbrowser/x/lib/browser/y';`. Side-effect imports are
already an idiom in this tree, so such a backwards import would be invisible to the
backwards-edge AND undeclared-edge assertions at once. The file's header honestly discloses the
restriction; the doc comment at `:123` does not. Widening the matcher is chosen over narrowing
the comment because it closes the hole and leaves the doc comment true as written — but only if
the widening stays anchored to a real import statement, because a bare substring scan mints
phantom edges from prose in six extensions, which is precisely what the header warns about.

Separately, `GUI-DEFECTS.md:47` says "tab-uris now builds before token-gate but imports from
it". Plan 08 reversed that; the chain is now `branding → token-gate → tab-uris → …`. The row's
OPEN status is correct and stays; only the note is wrong.

Output: a widened, comment-stripped edge derivation with a plant for the side-effect form, two
corrected comments in the gate, and one corrected note in the defect list.
</objective>
