<objective>
Close two `minor` GUI conformance gaps that are both about a gate the tree does not yet have:
**G-14.1.1-19** (overlay creation must log no TypeError from the shell window's `gBrowser` stand-in)
and **G-14.1.1-24** (a `--quick` row must prove that exactly one backend file reads the
product-prefixed environment keys off the live process environment).

Purpose: the TypeError is harmless to the page but fires on every overlay creation and hides the
next real chrome-side error, which is the class of failure CLAUDE.md's first verification rule
exists to protect. The env gate covers the class of bug behind GUI-DEFECTS item 9 — the scrub runs
before `tab-uris` loads, so the next backend module to read the live environment directly reads
nothing and fails silently, exactly as item 9 did.

Output: a stand-in that implements exactly the member set upstream calls on it, and two new
derive-and-compare `--quick` gates, each with a `--self-test` that plants faults and requires each
to go red naming the drift.

plan 03's two commits have landed.

The gap's literal truth is "Exactly one backend file reads `process.env.POWERBROWSER_*`, and a
`--quick` row proves it". Measured against this tree that statement is false in both halves: **zero**
backend files read a prefixed key directly off the live environment, and the two files that touch the

the post-execution verifier would read it as UNMET.

product-prefixed key off the live process environment, and the set of backend files touching that
environment at all is pinned to two reasoned entries by a `--quick` row. This is the same protection
the gap wanted, stated in terms the tree can satisfy.
