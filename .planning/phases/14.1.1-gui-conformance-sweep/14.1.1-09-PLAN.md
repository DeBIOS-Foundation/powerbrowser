**CR-03 (⚠️ Warning, a CLAUDE.md hard-rule violation).**
`theia/extensions/modes/src/browser/setups-service.ts:510-513` throws a user-facing string whose
first token is the internal command id `powerbrowser.setups.open-dependent:`, and Theia surfaces
it verbatim. It predates this phase (commit `17ee47a`, `feat(14-03)`), but the copy gate added
this phase was built to guard exactly this file and cannot see it: `derivedServiceCopy` enumerates
four paint sites and `throw new Error` is not one of them. The only real copy violation in the
guarded file is invisible to its guard. There is a second half the verification did not measure:
`SETUPS_OPEN_DEPENDENT` in `setups-commands.ts:35-37` carries **no `label`**, so it appears in no
command palette — the sentence's closing next step names an affordance that is not on screen,
which the user-facing-copy rule forbids just as squarely as the identifier does.

**WR-02 (⚠️ Warning).** `theia/extensions/modes/src/browser/modes.css:591` claims
`gui09-setups-copy` "goes red on a third" danger selector. The gate makes no such assertion — it
tests only that the one dialog class the service tags has a danger-scoped rule. A comment that
credits a check with an assertion it cannot make is an absence claim over an instrument that can
never produce it, which is CLAUDE.md verification rule 1.

**ℹ️ web-tab reopen.** `theia/extensions/tab-uris/src/browser/web-tab.ts:509` reads
`reply.ok !== true`, where the class's own `lostReply()` predicate (`:345-347`) also folds
`where === UNKNOWN_TAB_OUTCOME`. A reply that is `ok: true` with an `unknown-tab` outcome would
read as a successful reopen and leave the body blank — the same defect class G-14.1.1-4 closed one
site earlier.

Purpose: three findings, one theme — a statement in the tree that is not true of the tree. The
fixes are small; leaving them is what CLAUDE.md's rules are written to prevent.

Output: one contracted copy constant replacing an internal identifier, one widened paint-site

at the site that was reading around it.
