## Decisions Made

- **Four contract rows, not two.** The plan named the two new failure errors. Set equality could not close with them alone: `SETUP_GONE_TABS_NOTICE` and the two `pickSetup` quick-pick placeholders (`Restore Setup`, `Delete Setup`) are painted by the service and shipped in Phase 14 with no row in the table. Documenting already-shipped copy is contract completion, not new copy — the literals are byte-identical to what the service already flashed.
- **Derivation by paint site, not by "exported string constant".** `SETUPS_STORE_FILENAME` is an exported string constant and is not user copy. Enumerating the call sites that actually paint (flash arguments, quick-input fields, ConfirmDialog fields, `pickSetup` arguments) excludes it structurally, with no hand-kept exclusion list, and matches what "user-facing" means.
- **`SETUP_ROW_LABELS` is a scope selector.** The Copywriting Contract table is shared across four surfaces, so the gate has to be told which rows are setups. It restates no copy: every compared string is read from the tree at check time, so the gate still goes red on an addition and on a removal at either end.
- **ASCII apostrophes.** The plan's prose said "typographic apostrophe"; the neighbouring contract rows and the existing service constants all use ASCII `'` (U+0027). Byte-for-byte reproduction of the neighbours won over the prose. The em dash is U+2014 as specified.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Two extra Copywriting Contract rows beyond the two the plan named**
- **Found during:** Task 1
- **Issue:** The contracted gate compares the service's painted set against the spec table's setups rows as set equality. `SETUP_GONE_TABS_NOTICE` and the `pickSetup` placeholders `Restore Setup` / `Delete Setup` are painted by the service but had no table row (the gone-tabs variant is described in 14-UI-SPEC.md prose at :282, never as a contract row). Without rows for them the gate could not be built as specified — they would report forever as unreviewed copy.
- **Fix:** Added `Setup gone-tabs notice` and `Setup picker placeholder` rows carrying the literals the service already flashes, verbatim. No shipped string changed.
- **Files modified:** `.planning/milestones/v1.3-phases/14-modes-windows-setups/14-UI-SPEC.md`
- **Verification:** `node scripts/verify-gui09-setups-copy.mjs` → 17 painted strings match 17 contracted literals.
- **Committed in:** `5eae490` (Task 1 commit)

**2. [Rule 1 - Bug] The gate's CSS rule-block derivation could not see two adjacent rules**
- **Found during:** Task 2
- **Issue:** `derivedDangerClasses` anchored each rule block on `(^|\})`, consuming the previous rule's closing brace. Two adjacent rules therefore overlapped and the second was unmatchable — the new `.pb-setup-delete-confirm` rule was invisible to the gate even though it was correctly present in the sheet, and the check went red on a correct tree.
- **Fix:** Strip CSS comments first, then walk innermost `selector { decls }` blocks with no leading-brace anchor. Documented in the function's doc comment so the trap is not re-introduced.
- **Files modified:** `scripts/verify-gui09-setups-copy.mjs`
- **Verification:** The gate goes green on the correct tree and self-test plant 6 still goes red when the rule is removed — so the fix did not turn the assertion into one that can only pass.
- **Committed in:** `0bfbaa1` (Task 2 commit)

**3. [Rule 1 - Scope] The plan's basename self-exemption step was a no-op and was not implemented**
- **Found during:** Task 1
- **Issue:** The plan asked the gate to exempt itself from its own scan by basename, "the way the second-writer gate does". That gate walks a directory; this one reads three explicitly named files and can never read itself.
- **Fix:** Not implemented — dead code guarding an impossible condition. Recorded here rather than added.
