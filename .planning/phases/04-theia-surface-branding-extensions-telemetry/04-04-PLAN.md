# Phase 4 Plan 04 — Wiring close-out: theme, logo channel, Mozilla repoint, allowlist, propagation proof

**Goal:** Close every remaining Phase 4 surface: default theme + logo on
the 04-01 runtime channel (zero `.ts` literals left), Mozilla telemetry and
crash endpoints repointed or disabled per the manifest, configured
telemetry/URL hosts flowing into endpoint-allowlist coverage so
`verify-endpoints` passes for an arbitrary downstream, and the single-edit
propagation proof (rename in `configuration.toml` → every Theia surface
changes, no second file edited).

**Requirements covered:** GEN-05 (remainder: theme, logo, about dialog),
TEL-03 (all of it)

**Wave:** 4 (blocked on 04-03 — touches `scripts/generate.mjs`,
`config-schema.json`, branding extension sources, `verify-platform.sh`
registry; last plan of the phase)

## Research conclusions this plan builds on (do not re-derive)

- `theia.default_theme = "dark"` exists in manifest + schema but is
  UNCONSUMED (nothing reads it — confirmed by tree search). Target:
  application `package.json` `theia.frontend.config.defaultTheme` via the
  04-01 package.json-block mechanism.
- Logo: `brand/mark.svg` is the single source; `powerbrowser-mark.ts`
  carries a byte-identical copy asserted by `verify-branding-preflight.mjs`
  every run, and the favicon + welcome + about all render from it. A logo
  rebrand today = `.ts` edit = the exact thing GEN-05 forbids. Route the
  SVG through the 04-01 runtime channel (generated static asset); the
  `currentColor` in-shell vs `prefers-color-scheme` favicon split
  (documented in `powerbrowser-mark.ts` header, D-36) MUST survive the move
  — both exports' theme behavior is user-visible and already asserted.
- Gecko side (already in tree, currently STATIC literals in
  `emitFirefoxBrandingJs`): `toolkit.telemetry.server` blanked,
  `toolkit.telemetry.unified` false, `datareporting.*` false, health-report
  compiled out (`MOZ_SERVICES_HEALTHREPORT=False`, D-84), crash reporter
  disabled (`--disable-crashreporter` literal in `emitMozconfig`). TEL-03
  makes the Mozilla telemetry/crash endpoint values manifest-driven:
  `[telemetry]` endpoint and `[urls]` crash-report/homepage keys select
  repoint-vs-blank; the compiled-out flags stay as defence-in-depth.
- `verify-endpoints.sh` layers 1+3 read the TRACKED
  `powerbrowser/endpoint-allowlist.json` directly. Do NOT convert that file
  to generated output (its `reason` fields are hand-authored product
  decisions — generating them would erase the D-83..D-88 ledger). Instead:
  generator emits `generated/endpoint-hosts.json` (hosts derived from
  manifest telemetry endpoint + `[urls]` values); a new check asserts each
  is present in the tracked allowlist (set-equality, both directions —
  missing coverage AND stale entries fail, per the VER-01 stale-allowlist
  spirit and CLAUDE.md rule 2).

## Tasks

### Task 1 — Schema `[urls]` + remaining `[theia]` keys; theme/logo/about onto the channel

1. `scripts/lib/config-schema.json`: `[urls]` section — `support_url`
   (move/duplicate? `installer.support_url` already exists: REUSE it, do
   not create a second key for the same value — one setting, one path),
   plus `release_notes`, `update`, `crash_report`, `homepage`, `search`
   (all `required: false`, `https://` regex style). `[theia]`:
   `welcome_text`, `about_text` (`required: false`, plain-text regex in the
   established sink-safe style — these reach rendered UI; forbid
   `<>&"`-class injection characters at the schema layer, same
   defence-in-depth contract as `assertEmittable`). `default_theme`:
   constrain to known theme ids in `validate()` (reject unknown theme
   naming the key — a typo'd theme silently falling back is the failure).
2. `scripts/generate.mjs`: (a) `defaultTheme` block-apply to the
   application `package.json` (same block-surgical mechanism as 04-01's
   `applicationName` — extend it, don't duplicate it); (b) welcome/about
   text + logo SVG asset into the 04-01 runtime channel payload (new
   TARGETS rows; byte-identity + `--check` free); (c) FIXTURE_BASE +
   `--self-test` faults (bad theme id, markup-bearing welcome text, bad
   URL) each failing naming the dotted path.
3. Branding extension: welcome widget, about dialog, favicon contribution
   read ALL display values (name per 04-01, texts, logo, repo URL) through
   the runtime channel with existing literals as boot fallbacks; NO
   `src/**/*.ts` carries a brand value after this task (prove with a
   scan, not by reading). Preserve the inline-`currentColor` vs
   OS-`prefers-color-scheme` split and the `view:welcome` factory id
   (D-43), the `AboutDialog` guarded rebind (D-35), first-boot-only layout
   (D-24) — all load-bearing, all asserted by existing preflight sections
   that must stay green.

**Verify:** fixture rebrand (new name + texts + theme + logo SVG) →
generate → app-bundle-only rebuild → welcome, about, favicon, theme all
show fixture values; `git status` shows zero modified `theia/**/src/**`
(except this plan's own channel-plumbing commit); a tree-wide scan for the
fixture's PRIOR values in `theia/**/src/**` finds nothing.

### Task 2 — Manifest-driven Mozilla telemetry/crash prefs + allowlist coverage check

1. `emitFirefoxBrandingJs`: replace the static telemetry/crash pref lines
   with manifest-derived emission — `toolkit.telemetry.server` blanked
   when level is `off`, repointed to the manifest endpoint host when a
   level is set (derive pref names from `upstream/` `all.js` at check
   time where possible; where the tree is the source, cite file:line in a
   comment); crash-report URL pref (`breakpad.reportURL`-family — confirm
   exact key against upstream `all.js`, do not guess) blanked vs repointed
   per `[urls].crash_report`. Byte-identity against the tracked branding
   files is preserved by REGENERATING through the same emitter (the tracked
   files remain the comparand — regenerate, don't hand-edit, then confirm
   `generated-byte-identity` green on the shipped manifest).
2. New `scripts/verify-theia-endpoints.mjs` (honestly `--quick`: text off
   disk only): derives expected hosts from the manifest (telemetry
   endpoint + `[urls]` values via `resolveConfig` import — the same import
   pattern `verify-generated-identity.mjs` uses) and set-compares against
   `powerbrowser/endpoint-allowlist.json` hosts — missing coverage fails
   naming the host, allowlist entries covering no manifest host fail as
   stale (both directions, no hand-kept list). `--self-test` with planted
   faults: manifest endpoint host absent from allowlist, stale allowlist
   entry — each observed red. Also assert `verify-endpoints.sh` layer-1
   pref expectations still hold for the repointed/blanked prefs (the
   layer-1 `expect` values for telemetry prefs must now be derived from
   the same manifest resolution — one source, or the two gates can
   disagree; document which file owns the derivation).
3. `scripts/verify-platform.sh`: register new label(s) in `--quick`.

**Verify:** fixture manifest with telemetry on + custom crash URL →
generate → new check passes only AFTER adding the hosts to the tracked
allowlist (proves the check reads both sides); removing one host fails it
naming the host; `verify-endpoints.sh --layer 1` still green (or updated
in the same commit with derivation owned in exactly one place).

### Task 3 — Single-edit propagation proof + phase gate

1. Propagation drill (the GEN-05/TEL-03 acceptance in miniature): from a
   clean tree, change ONLY `configuration.toml` (`display_name`,
   `welcome_text`, `telemetry.level`+`endpoint`, one `[urls]` value, one
   extension version bump) → `node scripts/generate.mjs` →
   assert `git status` shows changes ONLY under `generated/`,
   `theia/applications/browser/package.json` (surgical blocks), and the
   tracked branding pref files (regenerated comparands) — no second
   hand-edited file. Record the full file list in the SUMMARY.
2. `scripts/verify-platform.sh --quick` fully green; every new registry
   row also passes via `--only <label>` alone. Preflight/byte-identity/
   agreement self-tests all green.
3. Update `scripts/verify-branding-preflight.mjs` theia sections whose
   hand-literal expectations moved to the channel: expectations stay on
   `brand-tokens.json` for Power Browser's own values; add the
   sources-carry-no-literals half for every new read site (each with a
   planted-fault row observed red). No other verifier semantics change —
   Phase 6 owns the verification rewrite.

**Verify:** the drill's file list contains no hand-edited second file;
`--quick` green; this plan's SUMMARY names the one intentional gap if the
full `--gate` (browser-boot layers) was not run, with the exact command
for the human/executor to run it.

## Per-plan verification (must all go red when broken)

- Revert the generated theme/logo payload but keep the manifest change →
  `--check` fails (stale detection, not fresh-generate luck).
- Fixture manifest with telemetry ON and endpoint host missing from the
  tracked allowlist → new coverage check fails naming the host (proves it
  reads the manifest, not a copy of the allowlist).
- Plant the previous release's display name in one widget source file →
  preflight sources-clean assertion fails naming the file (proves no
  literal drifted back in).
