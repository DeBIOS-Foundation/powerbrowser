# Phase 4 Plan 03 — Telemetry pipeline: level + endpoint + batching sender

**Goal:** `configuration.toml` declares telemetry level (Theia's real enum
`off`/`crash`/`error`/`all`, default `off`) and the downstream's own
endpoint; a new `@powerbrowser/telemetry` extension batches and retries
event delivery to that endpoint honoring the level; with level `off`
nothing leaves the application.

**Requirements covered:** TEL-01, TEL-02 (TEL-03 endpoint-allowlist flow is
04-04; Mozilla-side repointing is 04-04)

**Wave:** 3 (blocked on 04-02 — touches `scripts/generate.mjs`,
`config-schema.json`, `verify-platform.sh` registry)

## Research conclusions this plan builds on (do not re-derive)

- `@theia/core` ships ONLY the `TelemetryLogger`/`TelemetrySender`
  interfaces (`core/src/common/telemetry.ts`); there is NO default sender
  implementation anywhere in `@theia/*` (only `plugin-ext`'s forwarder to
  `this.sender?` and the `theia.d.ts` API surface). The sender is ours to
  write — this is new `@powerbrowser/*` extension code, not a core patch
  (hard rule 1).
- `telemetry.telemetryLevel` is a real preference (default `off`); the
  sender must read the live preference value per event (level changes at
  runtime must take effect without restart — assert this in a test).
- Crash scope for v1: Theia has no OS crash reporter; `crash` level means
  the `sendErrorData` path (uncaught errors / error telemetry). A fuller
  crash-report pipeline is explicitly v2 (TEL-04) — do not build it here.

## Tasks

### Task 1 — Schema `[telemetry]` + endpoint/level emitters

1. `scripts/lib/config-schema.json`: `telemetry.level` (`required: false`,
   default `off`; validate against the exact four-value enum in
   `validate()` with a named failure — the schema table has no enum
   mechanism, same treatment as 04-02's `source` allowlist),
   `telemetry.endpoint` (`required: false`, `https://` regex in the
   established style; unset + level ≠ off is a generate-time failure naming
   the key — an enabled level with nowhere to send must never build).
   Unset level defaults to `off` with the standard D-08 default-echo.
2. `scripts/generate.mjs`: TARGETS row(s) emitting
   `generated/theia-telemetry.json` (`{level, endpoint}`) for the
   extension to consume at runtime through the 04-01 channel pattern (do
   NOT bake the endpoint into compiled `.ts` — same no-recompile rule as
   branding). Sink guards on both values. FIXTURE_BASE + `--self-test`:
   level-enabled-without-endpoint fault, bad-enum fault, non-https
   endpoint fault — each fails naming the dotted path.

**Verify:** `node scripts/generate.mjs --self-test` green, new faults
observed red; `node scripts/generate.mjs --check` covers the new TARGETS
row (stale-output drill: hand-edit the emitted JSON → `--check` fails).

### Task 2 — `@powerbrowser/telemetry` extension: batching sender

1. New `theia/extensions/telemetry/` extension (`package.json` in the
   `@powerbrowser/*` style of `branding/`; frontend module binding a
   `TelemetryLogger`/`TelemetrySender` implementation; wire into
   `theia/applications/browser/package.json` dependencies and the root
   `theia/package.json` `build:extensions` script alongside the existing
   four). Implementation: in-memory batch queue, size + interval flush,
   exponential-backoff retry (bounded attempts, then drop with a console
   diagnostic — never unbounded growth, never a throw out of a telemetry
   path), per-event live read of `telemetry.telemetryLevel`
   (`off` → drop before queueing: nothing enqueued, nothing sent;
   `crash` → error path only; `error` → error path; `all` → usage +
   error). No PII enrichment — event name + caller-supplied data only.
2. Unit tests runnable WITHOUT a browser or build (plain node test over
   the queue/retry/level-gating logic with a stubbed fetch + controllable
   clock — honestly `--quick`-grade): off-sends-nothing, batch flush on
   size, flush on interval, retry-then-drop, runtime level change takes
   effect. Each test must fail against a stubbed-broken implementation
   (prove the test discriminates — CLAUDE.md absence-of-log-line lesson:
   the off test asserts zero fetch CALLS, which is valid only because the
   test also performs an on-level control send through the same stub in
   the same run proving the stub records calls).
3. No-network default proof: with the shipped manifest (level unset →
   `off`), extension loaded, run the unit suite + a backend boot smoke if
   cheap (`scripts/smoke-theia.sh` if it runs without display; otherwise
   the stub-level proof stands and the gap is named in the SUMMARY).

**Verify:** `yarn --cwd theia/extensions/telemetry build` (tsc) clean;
unit suite green; each level-gating test observed red against an
always-send stub; `scripts/diff-theia-core.sh` clean (no core touched).

### Task 3 — Registry rows

1. `scripts/verify-platform.sh`: register the telemetry unit suite (or a
   thin wrapper `.mjs` invoking it) as a `--quick` row + a self-test row
   proving the off-sends-nothing assertion can go red (run the suite

**Verify:** `scripts/verify-platform.sh --quick` green;
`--only <new-label>` passes alone; self-test row observed red pre-fix.
