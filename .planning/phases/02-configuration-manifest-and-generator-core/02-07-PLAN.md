<objective>
Score the never-audited fourth design for G-02-11 / G-02-12 against the panel's first-ranked one,
and record the operator's ratified choice as a durable, machine-readable artifact that plan 02-08
branches on.

Purpose: G-02-11 (byte-identity is a false RED everywhere but this machine) and G-02-12 (preflight
is a false GREEN everywhere, including where the file is broken) are two directions of one root
cause — an absolute checkout path baked into tracked files and into the expectations that check
them. The 17-agent panel recorded in `02-UAT.md` ranked *option 1, quotient out the checkout root*,
first, but flagged a fourth option that never went through it and wrote, in as many words, that it
"should be scored against option 1 before implementation, not assumed better or worse." This is a
one-way door: it changes the format of tracked files and the contract of a shipped gate. It gets
scored and ratified before a line of it is implemented.

Output: `02-DESIGN-G-02-11.md` in this phase directory, carrying the scorecard, the ratified verdict
as one of two literal tokens, and the expected behaviour of both `--quick` rows at a checkout that
is not this machine's.

**Why there is no `type="tracer"` task here.** TRACER_MODE is on for this plan set and the tracer
lives in 02-08, where the first code lands. This plan writes one markdown file and asks one
question; the thin end-to-end slice of a decision is the decision.

**The three-line shared-prefix closure**, which option 1 must carry and which the panel verified
against every case. It runs BEFORE the regex is built:

```js
const after = fixed.slice(1);
const seg = /^\/[^/\n]+/.exec(after[0])?.[0];
if (seg !== undefined && after.every(f => f.startsWith(seg))) return null;
```

**Option 1 — `option-1-quotient`.** `Buffer.compare` still runs first and still decides. Only once
it has failed may a fallback ask one question: are these the same bytes at a different absolute
root? A helper splits the generator's own output on the root it just emitted at, turning the emitted
bytes into literal fragments with a hole wherever an absolute path went; the fragments are escaped
into an anchored regex and matched against the tracked bytes. The captured string must not span a
line, must be identical at every hole, and must be absolute. Otherwise the plain byte failure
stands. No path is written down anywhere.

**Option 4 — `option-4-placeholder`.** The tracked `.desktop` files stop carrying an absolute path
at all and carry a placeholder token instead, substituted at install time. Byte comparison stays
exact with no normalisation logic; G-02-12 dissolves because there is no absolute literal left on
either side of the preflight's comparison. The cost is that the tracked entry is no longer directly
usable without a substitution step, and that the preflight loses its ability to check a *real*
absolute path, which is what `inventory/brand-tokens.json`'s hand-write block calls Pitfall 4.

**The criterion nobody has answered yet, and the reason this scoring is not academic.**
`branding-preflight` and `generated-byte-identity` are BOTH rows of the base `CHECKS` array that
`scripts/verify-platform.sh --quick` runs (`scripts/verify-platform.sh:3505` and `:3627`). G-02-11's
failed truth is *"on a clean clone … `--quick` runs to completion green."* Under option 1, once
G-02-12 is closed by live-deriving the preflight's root, a tracked `.desktop` naming this machine's
path is HONESTLY wrong at a foreign checkout — so `branding-preflight` goes red there and `--quick`
is still not green on a fresh clone, for a true reason instead of a false one. Under option 4 there
is no absolute literal left to be wrong, so both rows are green. The scorecard must state this
outcome for each option explicitly; it is the single largest difference between them, and the panel
never saw it because option 4 was raised after the panel launched.

**Binding constraints either option must satisfy** — CLAUDE.md, plus `02-RESEARCH.md` Pitfall 7:

- The preflight's expected values may never come from `configuration.toml` or from
  `scripts/generate.mjs`. A gate that reads the same source the generator writes from agrees with
  itself no matter how wrong both are.
- Adding a check means appending one row to `scripts/verify-platform.sh`. Never a sibling driver.
- Derive from the tree and compare; do not hand-keep an expectation list.
  `inventory/brand-tokens.json`'s `repo_root` key is exactly the hand-kept absolute expectation this
  rule forbids.
- No internal identifier — a host path included — may appear in user-facing PASS or FAIL copy.
- The repo must live at a path containing no space character. The panel found option 1's helper as
  proposed accepts a space-bearing root and nothing else in the tree catches it.
