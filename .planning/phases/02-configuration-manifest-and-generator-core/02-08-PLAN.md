### Branch A — `option-1-quotient`

**`scripts/verify-generated-identity.mjs`.** Add one exported helper,
`sameFileAtADifferentRoot(wantText, haveText, emittedRoot)`, returning the captured root string on
success and `null` otherwise. Its body, in order:

1. `const fixed = wantText.split(emittedRoot);` — the emitted bytes become literal fragments with a
   hole wherever the root went.
2. `if (fixed.length === 1) return null;` — the emitted file contains no occurrence of the root, so
   there is nothing to quotient out and the plain byte failure stands.
3. The three-line shared-prefix closure, verbatim, BEFORE the regex is built:

```js
const after = fixed.slice(1);
const seg = /^\/[^/\n]+/.exec(after[0])?.[0];
if (seg !== undefined && after.every(f => f.startsWith(seg))) return null;
```

4. Escape every fragment for use as a literal in a regex (`replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`),
   join them with the capture group `([^\n]*)` so a capture can never span a line, and anchor the
   whole pattern with `^` and `$` and NO `m` flag.
5. Match against `haveText`. No match returns `null`.
6. Reject unless every capture is the identical string (`new Set(caps).size === 1`).
7. Reject unless that string starts with `/`. A relative capture is not a checkout root.
8. Reject if that string contains a space character. CLAUDE.md hard rule 4 forbids a repo path with
   a space, and `pkgs.mkShell`'s space-separated `NIX_LDFLAGS` is why. This rejection is reported as
   its own named failure, not folded into the generic byte failure, and its message does not print
   the offending path.
9. Return the captured string.

Call it from inside `compareAgainstTracked`'s `for (const tracked of EXPECTED)` loop, only after
`Buffer.compare(want, have) !== 0`, passing `REPO_ROOT` as `emittedRoot`. On a non-null return, push
no failure and count the target into a `relocated` tally. On `null`, push the existing byte-failure
message unchanged.

**PASS copy.** The PASS line reports the tally without the path: it states how many files are
byte-identical and, when the tally is non-zero, how many matched only after accounting for a
different checkout location. It never prints the captured root.

**`scripts/verify-branding-preflight.mjs`.** Replace `exp.repo_root` at both use sites with a root
derived from the `root` argument `runChecks` already receives — `const repoRoot = resolve(root);` —
so `wantExec` and `wantIcon` describe the tree being checked. `root` is a filesystem fact, not a
manifest value, so Pitfall 7's independence is preserved: nothing here reads `configuration.toml` or
`scripts/generate.mjs`.

**`inventory/brand-tokens.json`.** Delete the `repo_root` key from `brand_display_expectations`. It
has exactly two readers, both of them the lines just replaced.

**Consequence to record, not to hide.** With that change a tracked `.desktop` naming this machine's
path is honestly wrong at a foreign checkout, so `branding-preflight` goes red there and `--quick`
is non-zero on a fresh clone. That is what `foreign_checkout_preflight_exit: 1` in
`02-DESIGN-G-02-11.md` records, and task 1's verify compares against it rather than assuming green.

<relocation_harness>
Every "at a foreign checkout" proof in this plan uses this harness. It is written down once so that
three tasks cannot each invent a slightly different one.

```sh
D="$(mktemp -d)/pb"
git clone --no-hardlinks -q . "$D" && git ls-files -z | tar --null -T - -cf - | tar -xf - -C "$D"
```

`git clone` supplies a real `.git`, which both gates need — `verify-generated-identity.mjs` runs
`git ls-files` and `git check-ignore` and reports a distinct failure when version control cannot be
read. The `tar` overlay then replaces the cloned HEAD content with the CURRENT tracked working tree,
so the harness tests the edits under review rather than the last commit. Only tracked files are
copied, so `upstream/`, `objdir*/`, `node_modules/` and `generated/` never enter the copy — the whole
tracked tree is 236 files and the clone is under 3 MB. `mktemp -d` yields a path with no space
character, which CLAUDE.md hard rule 4 requires. Remove the parent of `$D` when done.
</relocation_harness>
