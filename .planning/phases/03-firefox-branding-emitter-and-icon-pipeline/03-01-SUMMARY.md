## Decisions Made
- Spike Q1: direct `../generated/` path rejected (`Attempting to process file outside of allowed paths`); fallback proven with exit-0 configures for dev and release. The `--with-branding` VALUE must sit exactly 3 levels under topsrcdir (the branding `moz.build` `../../../` include); a link one level deeper puts the value at depth 4 and goes red -- proven by a failed configure in-session.
- Spike Q2: mozconfig `export MOZ_APP_VENDOR/UA_NAME` lines satisfy configure with zero diff on all resolved lines -- exports preferred, no patch touch, no `identity.configure` needed for these two values.
- Spike Q3: inkscape 1.4.4 already inside `.#firefox` -- RESEARCH assumption A2 closed, no flake change.
- aboutDialog.css and pref/firefox-branding.js get literal-emit rows: the plan's action fragment for them was truncated mid-sentence, but the must-have truth demands a *complete* drop-in dir and `content/jar.mn` packages `aboutDialog.css`, so omitting them breaks the build. - Agreement checker SKIPs (exit 0) on an absent tree and FAILs on a present-but-empty one -- the 02-06 fresh-clone lesson applied to the new row; the plan's literal "empty set fails" reading would reintroduce the gate readers learn to skip.
- Overlay symlink is setup-created, not committed: the committed variant was tried and reverted -- the residue scan reads a tracked symlink as EISDIR and fails. Same mechanism as the existing `upstream/powerbrowser` overlay.
- Default-env `configure`/`build` stays red until 03-02 lands emitted PNGs (FINAL_TARGET_FILES); tree parked green on tracked dev meanwhile. Full-suite `smoke-firefox` failure is that gap, not a defect here.
- GEN-01 left open: `identity.configure` and the tier-3 Linux build are 03-04 scope. `requirements-completed` is empty and no mark-complete was run; 03-04 closes the requirement.
