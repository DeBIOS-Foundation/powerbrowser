## Decisions Made

- **Specifier-only edge derivation.** Confirmed empirically before writing the deriver, per
  the plan's `read_first`. An `@powerbrowser/<name>` occurrence outside a `from '...'`
  specifier is not an edge.
- **Edges are matched by package name, not by directory spelling.** The gate builds a
  `directory -> package short-name` map from each extension's own manifest, so an edge is
  matched by the package it actually names.
- **An unresolvable `@powerbrowser` specifier is a named FAIL.** An import naming no
  extension under `theia/extensions` is a real defect class (an unresolvable workspace
  import), so it is reported rather than skipped.
- **Empty derivations fail distinctly as a broken instrument.** Zero chain entries, zero
  extensions or zero edges each produce their own message saying the comparison proves
  nothing — never a vacuous pass. Three of the seven planted faults exist to prove this.

  exactly as it was. Every subsequent commit in this plan used the pathspec form.

## What this plan did NOT prove — read this before flipping G-14.1.1-9

**The literal clean-checkout `yarn build:extensions` was not run, and that is a recorded
deferral rather than an oversight.**

`G-14.1.1-9`'s root cause suggests proving the fix with a check that removes
`theia/extensions/*/lib` and runs `yarn build:extensions`. Running that here would have:

1. deleted the `lib` trees a concurrent session's **running sidecar is currently served
   from**; and
2. compiled that session's uncommitted TypeScript — in `mode-service.ts`,
   `modes-frontend-module.ts`, `group-actor-client.ts`, `main-area-exemption.ts`,
   `browser-window-command.ts` and `tab-query-service.ts` — into those trees.

Deleting another session's build outputs to prove a build order is a worse defect than the
one being fixed. The proving check here is therefore the static `--quick` pair, which asserts
the ordering and declaration invariants a clean build depends on, **not the clean build
itself**. That distinction is stated in the script's header and in the registry comment so a
later reader cannot mistake the row for the build.

**Consequence for plan 10: flip `G-14.1.1-9` to `in_tree`, never to `fixed`.** The clean-lib
build belongs to pass 3, from a quiet tree.
