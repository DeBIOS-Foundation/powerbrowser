<objective>
Derive the release identity from configuration.toml (REL-01).

Purpose: a release is named by one key, `v<ESR>-<revision>`. The key is computed from the ESR pin
(plan 40-01) and a new integer `[product] revision`. The version files that later release
tooling reads (Phase 44 descriptors, Phase 49 release.yml) are generator output with tracked
comparands, so a hand-written version literal or a descriptor that disagrees with the key goes
red at `--quick` tier.

The version files are release metadata, not a Gecko build input. Feeding a revisioned display
version into Gecko clears IS_ESR (RESEARCH Pitfall 3).

Output:
- the schema key and validator branch
- `releaseIdentity()`
- two version-file emitters with tracked comparands
- the fixture churn that a new required key implies
- `scripts/verify-release-identity.mjs` with two quick rows
</objective>
