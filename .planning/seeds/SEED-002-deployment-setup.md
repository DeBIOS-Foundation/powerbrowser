# SEED-002: Deployment setup

A single owner who cannot do much by hand runs PowerBrowser as a real product: one installer per OS on GitHub Releases, self-update through the built-in updater, Firefox ESR and Theia tracked automatically, bug reports and support on GitHub, opt-in error telemetry, a website at powerbrowser.org, and every recurring job automated with a defined signal to the owner. No server.

## Provenance

Produced 2026-10-20 by two adversarially verified workflow runs (8 agents on packaging options, 12 agents on the production plan: five research lenses, five verifiers, one synthesizer, one completeness critic). Every refutation and critic finding is applied in this text. Items the critic or a verifier could not check are listed under "Unverified". No build was run. Owner approvals on 2026-10-20: the per-OS format plan (section 1) and the request to seed this plan under the name "Deployment setup".

## Two facts that change the schedule

- Mozilla ships an ESR 153 point release every two weeks, not four (https://whattrainisitnow.com/calendar/: 153.6 on 2026-10-27, 153.7 11-10, 153.8 11-24, 153.9 12-08, 153.10 2027-01-12, ... 153.22 and ESR 175.0 on 2027-06-29, 153.27 on 2027-09-07). - The tree is one security release behind today: 153.5.1esr shipped 2026-10-20 under MFSA 2026-112 (product-details FIREFOX_ESR "153.5.1esr"; tags FIREFOX_153_5_1esr_BUILD1 and _RELEASE at 6cd88e7d). The pin is FIREFOX_153_5_0esr_BUILD1 (configuration.toml:115).

## 1. Packaging format plan (approved 2026-10-20)

- Mac: Firefox packaging. `mach package` makes a universal DMG plus a MAR, cross-built on legion and signed with rcodesign. Needs an Apple Developer ID for notarization.
- Windows: Firefox packaging. `mach repackage installer` makes the NSIS setup.exe plus a MAR, cross-built on legion.
- Linux: Firefox packaging. `mach package` makes a tar.xz plus a MAR. This is the canonical Linux download and the only Linux format that updates itself from GitHub.
- Nix: a flake package that repacks that same Linux tarball the way nixpkgs' floorp-bin repacks Floorp, with the built-in updater turned off (DisableAppUpdate policy; the Linux is-packaged-app check is GTK-only, so darwin needs the policy too). Nix users update through the flake. A binary cache is required or every install compiles Gecko. x86_64-linux first; aarch64-darwin only after a signed DMG exists; nixpkgs drops x86_64-darwin after 26.05.
- Flatpak (later): own Flathub manifest on org.mozilla.firefox.BaseApp built from the same tarball, --persist=.debios. `mach repackage flatpak` refuses any product except firefox and thunderbird (upstream/python/mozbuild/mozbuild/repackaging/flatpak.py:186-191). Resolve Flathub's build-from-source rule first.
- Later, on demand: AUR -bin (community), winget, Homebrew tap then cask, .deb/.rpm with own repositories (they turn the updater off), AppImage.
- Skip: MSI (Windows-host-only, WiX), MSIX, macOS PKG, Snap.
- Nix is not a Mac or Windows channel. Mac users need the notarized DMG. WSL runs the Linux build under WSLg but cannot be the Windows default browser and Windows links never reach it; Windows users need the .exe.

Mozilla's own CI runs every one of these repackage steps on Linux workers except MSI (upstream/taskcluster/kinds/repackage/kind.yml, repackage-msi/kind.yml), so no Mac or Windows build host is needed. Free GitHub-hosted macos-26 runners are the fallback for the macOS build (Zen uses them for its universal build).

## 2. Principles

1. Automation first. Every recurring job has a machine trigger and a defined signal to the owner. A job the owner must remember is a defect.
2. No server. GitHub Free, Cloudflare Free and legion cover every workload. Only a Nix cache above 5 GB without Cachix, or a crash receiver above the 100 MB Worker request cap, could force a VPS; both have serverless fallbacks.
3. One updater. Gecko's MAR updater is the only update mechanism for Gecko, Theia, the @powerbrowser/* extensions and the bundled Node; one complete MAR carries all of them. Package-manager channels turn it off.
4. Opt-in telemetry. JS error reports go to a project-owned Worker only when the user raises the preference; no product analytics; no Mozilla telemetry; crash reporter disabled until the Glean crash ping is patched out.
5. Derive and compare, never hand-keep (CLAUDE.md). Every check added here derives its expectation from the tree.
6. No GitHub-issued secret reaches legion through Actions (docs/RELEASING.md:481). The MAR key store, the Codeberg deploy token and a Safe Browsing keyfile do live on legion by design; GitHub secrets live in environments (repository-level secrets stay at zero, RELEASING.md:473) or in a Cloudflare Worker.
