<objective>
Ship an unsigned Windows x86_64 installer built entirely on Linux: a pinned cross-compile shell, a generator-emitted Windows mozconfig with the maintenance service off, one hook-only patch that makes the NSIS installer fork-owned and ping-free, a win32-x64 Theia sidecar with a pinned Node runtime beside it, and a guest-run install matrix that gates the asset onto the Release.

SEC-03 is carried here and is split, not dropped. The half that ships: the unsigned posture written into the build rather than into a runbook, meaning `--disable-maintenance-service` in the emitted mozconfig (the service would otherwise run updater.exe as LocalSystem with the Authenticode check compiled out), no `CERTIFICATE_*` NSIS defines anywhere on the installer surface, and the SmartScreen consequence captured verbatim from a real guest into tracked docs/WINDOWS-DISTRIBUTION.md and asserted against the live download page. The half that is deferred: Authenticode or Azure Artifact Signing, the maintenance service that depends on it, and MSIX. Both halves are recorded under the literal id `SEC-03` in docs/BUILD.md's Windows signing deferrals subsection, whose resume pointer names the later signing stage, and task 2's verify greps for that id so the pointer cannot vanish.

Purpose: the Linux release pipeline exists; this stage adds the second target without adding a signing dependency, and without letting an unsigned posture ship silently. Five claims the scope carries are unverified against this tree, and the first task settles them before anything is built, because each one selects a different implementation.
Output: probe record with five verdicts, .#firefox-win64 shell, powerbrowser/packaging/mozconfig-win64, a tracked Node runtime pin, generated installer artwork and defines, patch 050, widened installer gates, a Windows matrix gate, a Windows copy document behind its own gate, the WINNT descriptor row, a build-windows release job, a provisioned pkg-win11 guest, and a recorded green matrix.
